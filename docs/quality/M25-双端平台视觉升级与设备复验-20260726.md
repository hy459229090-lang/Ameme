## 结论

iOS 已从历史式“半透明卡片/胶囊堆叠”收敛为内容优先的原生 iOS 26 表达：暖白画布、平面单列时间流、一个搜索/设置玻璃控制面和一个 prominent glass 记录入口。玻璃只承担导航和操作层，不进入正文列表；iOS 18–25 使用系统 Material fallback。

Android 已按当前生产可用的稳定 Material 3 复盘：Compose BOM `2026.06.00` 对应 Material 3 `1.4.0`，不把仍为 alpha 的 Expressive API 作为发布依赖；完整补齐明暗色、类型、形状、受控动态色、大字号响应式事件行和单一高强调 FAB。可见图标已从停止维护的 `material-icons-extended` 迁移到官方 Material Symbols XML。

两端继续共享“今天 / 搜索 / 设置 / 单一记录入口 / 明确事实状态 / 演示数据不写入本机”的产品语义，但不做像素级同构。固定 Mock 路径可完整体验且不污染真实数据库，真实本机路径和既有核心闭环回归没有因视觉升级退化。

## 官方平台依据

- Apple：Liquid Glass 用于 controls/navigation；SwiftUI 通过 `glassEffect`、glass button styles 与系统 toolbar grouping 获取平台行为。正文内容不应被无差别玻璃化。
  https://developer.apple.com/videos/play/wwdc2025/323/
  https://developer.apple.com/documentation/swiftui/glasseffectcontainer
- Android：Material 3 theme 由 color/type/shape 组成，动态色应通过主题管理；Material 3 Expressive 是下一阶段方向，但稳定生产依赖仍应与稳定 release 对齐。
  https://developer.android.com/develop/ui/compose/designsystems/material3
  https://developer.android.com/jetpack/androidx/releases/compose-material3
- Android：Compose BOM `2026.06.00` 为本轮稳定基线；Material Icons 库已不再维护/推荐，官方建议使用 Material Symbols XML。
  https://developer.android.com/develop/ui/compose/bom
  https://developer.android.com/develop/ui/compose/graphics/images/material
- Android：FAB 用于单个高强调主操作，通常位于右下方。
  https://developer.android.com/develop/ui/compose/components/fab

## 已关闭问题

1. `P1 / iOS platform fidelity`：历史式卡片/胶囊材质过多；改为原生 Liquid Glass 控制层与平面内容。
2. `P1 / iOS accessibility responsiveness`：XXXL 搜索/设置图标重叠；固定视觉尺寸，保留语义和触控面积。
3. `P1 / iOS test brittleness`：横屏后查找远端固定 LazyVStack 行依赖虚拟化；改为先证明远端事件可达，再验证横屏可见结果与设置操作。
4. `P1 / Android icon currency`：停止维护的 Compose Material Icons 依赖；迁移官方 Material Symbols XML。
5. `P1 / Android hierarchy`：旧紫色卡片和状态胶囊造成多重高强调；保留单一 FAB 主操作，状态改为清晰文字。
6. `P1 / Android large type`：时间、事件和状态存在横向拥挤风险；大字号切换纵向布局，200% 设备截图复验。
7. `P2 / cross-platform copy`：演示模式提示过重；两端统一为简短可见提示，完整隔离语义由辅助功能和设置承载。
