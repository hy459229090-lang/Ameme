# P0 双端本机恢复候选与删除水位验证

## 结论

Android 与 iOS 生产本地存储现已在 Event 删除事务中写入不含正文的持久 deletion watermark/tombstone。水位绑定 space、对象类型、对象 ID、终态 revision、删除时间、原因和摘要；Android 以 schema trigger 禁止删除或 revision 回退，iOS envelope 在每次加载时重算摘要并拒绝重复键、无效 Event ID、正文 Event 与 tombstone 同时存在等不一致状态。

双端还加入独立于结构化导出和 pending-action/export snapshot 的同安装恢复 artifact：

- Android 对完成 WAL checkpoint 的 SQLCipher 文件生成一致快照，manifest 记录 schema/hash/size/全库删除水位摘要，并以当前数据库 key 做 HMAC；发布前对副本执行 SQLCipher `cipher_integrity_check`、SQLite `integrity_check`、schema、水位、hash 和 MAC 校验。
- iOS 对完整 AES-GCM envelope 与当前 Event 引用的 app-owned media 密文生成精确清单，manifest 记录 hash/size/水位摘要并以 Keychain key 做 HMAC；验证拒绝路径逃逸、symlink、额外文件、缺失/损坏媒体、错 key、未知 schema 和内部关系不一致。
- 恢复默认只写入不存在的新候选目录，不 merge、不覆盖 live store，也不自动切换为当前数据。调用方提供的权威删除水位比备份更新时，旧快照直接拒绝，不以“先恢复再删除”制造短暂复活。
- 双端现另有不接普通用户 UI 的同安装显式激活 API：授权精确绑定 candidate backup ID、确认 ID 和最长 15 分钟窗口；激活前后重验候选、密文/数据库/媒体关系与调用时权威水位。HMAC `PREPARED/COMMITTED` journal 让调用失败或重启明确回旧 live 或保留已验证新 live，原候选始终保留，伪造 journal fail closed。

两端 manifest、activation authorization 与 receipt 都硬编码 `production_recovery_claim=false` 与 `external_same_install_required`。artifact 不复制 SQLCipher raw key、Keychain/Keystore key、Agent pairing secret 或 pending action。当前 key 仍分别绑定 Android Keystore 与 iOS `ThisDeviceOnly` Keychain，因此本切片只构成可验证的本机恢复 Oracle 与同安装原子切换内核，不是跨设备、全设备丢失或生产灾难恢复。

## 未关闭 Gate

- 用户自有存储与 E2EE 云备份路线尚未决策；recovery secret 的建立、轮换、遗失、退出迁移、恢复 UX 与支持流程均未实现。当前设备密钥丢失后 artifact 不可解密。
- Android 物理设备上的 SQLCipher checkpoint/copy/open、Keystore、16 KB、空间不足、进程终止与 OEM 存储提供商尚未演练；iOS 真机 Keychain、文件保护、媒体大文件、后台/断电与磁盘故障尚未演练。
- 目前没有把本机恢复 Oracle 或 exact-confirmation 激活 API 暴露为普通用户“备份/恢复”入口，因为在 key recovery 路线未批准前这样做会造成灾难恢复误导。用户可见状态、候选解释、确认切换和支持文案仍是生产恢复 Gate 的一部分。
- 当前 watermark 只关闭本机 Event 删除及其 Coverage/长期 Memory 依赖的不复活；来源级 cascade、Raw/索引/ContextPack/摘要、peer ack、分布式 authoritative watermark 与物理删除证明仍待 DEL-01/SYNC-01。
- T0 8 人 × 7 天真实 Pilot、双端物理设备/读屏、签名/Provisioning、商店、真实 Agent 宿主、生产账号和安全/发布负责人签收继续 `hold`。
