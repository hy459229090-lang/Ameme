# P0 双端普通用户同安装恢复与健康状态验证

## 结论

双端设置页已把既有同安装候选与可回滚激活内核接成普通用户可执行的最小恢复闭环：

- 用户可创建或更新一个有界恢复点；管理器只保留 `current`、`previous`、`candidate` 和短时
  `next-*` 槽位，不生成无界快照。
- “已验证”不是 manifest 存在或静态 hash 通过：新点发布前必须真实恢复到隔离候选并成功打开，
  损坏、错 key、额外文件、路径逃逸、旧删除水位或关系错误均 fail closed。
- 新点验证失败时保留旧 `current`；候选激活仍精确绑定 backup ID 与最长 10 分钟确认，底层继续
  使用 `PREPARED/COMMITTED` HMAC journal 回旧 live 或保留已验证新 live。
- 设置页显示健康、创建时间、最近验证和最近成功恢复；切换前要求逐字输入 `恢复`，并明确后续
  本机修改会被恢复点替换。
- Android 激活前停止 Agent runtime、从 Compose 生命周期中摘除并关闭 SQLCipher repository；
  成功或安全回退后重开真实 repository、重载事件与 Today summary。iOS 恢复根位于 live
  `Application Support/Ameme` 的同级受控目录，避免移动 live 根时把恢复点一起移动。
- 最近成功恢复只保存绑定 backup ID 的无正文 receipt；日志只记录 commit、receipt、repository
  reopen 等布尔/枚举结果，不记录正文、路径、密钥或异常文本。
- 删除当前本机 Space 会精确清除同安装恢复根；即使清理失败，已提交的 SPACE root watermark
  仍阻止旧点重新激活。

该闭环只适用于当前安装和当前设备密钥仍存在的情形。Android 点位于 `noBackupFilesDir`，
iOS 点依赖 `ThisDeviceOnly` Keychain key；卸载、换机、设备丢失或密钥丢失后不可恢复。
artifact 与 receipt 继续硬编码 `production_recovery_claim=false`。因此它是诚实可用的同安装
恢复，不是云备份、跨设备恢复或生产灾难恢复，生产恢复 Gate 继续 `hold`。

## 判定

`P0-LOCAL-RECOVERY-USER-VISIBLE-MOBILE-06` 关闭了仓库内“普通用户无法创建恢复点、无法看到
真实健康、无法明确切换、恢复成功后看不到结果”的可执行空白，结论为 `conditional_pass`。
它没有关闭生产恢复路线，不得把 Swift Smoke、AVD 或静态 Gate 扩写为跨设备、全设备丢失、
物理恢复、真实用户或封闭 Beta 发布通过。
