# P0 双端本机恢复候选可回滚激活内核验证

## 结论

双端已把“认证同安装备份恢复到隔离候选”继续推进为一个不接普通用户 UI 的可回滚
live-store 激活内核：

- 激活授权精确绑定候选 `backup_id`、确认 ID 与最长 15 分钟窗口；过期、错误 backup 或把
  `productionRecoveryClaim` 设为 true 均在文件变更前拒绝。
- 激活前后都验证当前设备密钥、manifest MAC、schema、密文/数据库完整性、媒体关系和调用时
  权威 deletion watermark。原候选只被复制，不被移动、覆盖或删除。
- Android 要求 SQLCipher repository 已关闭且 live DB 没有 WAL/SHM/journal sidecar，再把候选
  复制到 live 同卷 staging；iOS 在 `MainActor` 同步冻结 store，并在 staging envelope 中把
  app-owned media locator 从候选根重写到最终 live 根。
- HMAC crash journal 只含版本、`prepared|committed`、确认 ID、backup ID 与 MAC，不含正文、
  path 或 key。`PREPARED` 失败/重启时只要旧 rollback 存在就恢复旧 live；新 live 完成全部复验
  后才写 `COMMITTED`，此后启动保留新 live 并完成旧 rollback 清理。
- 伪造/损坏 journal、symlink、保留文件冲突、候选漂移和旧水位均 fail closed。commit 后仅清理
  未完成时返回 `cleanupPending=true`，不把已 commit 的新 live 误报为已回滚。

artifact、authorization 与 receipt 始终为 `productionRecoveryClaim=false`。该内核仍依赖当前
安装的 Keystore/Keychain key，不提供 recovery secret、用户自有存储或 E2EE 包、跨设备 key
恢复、备份健康 UI、普通用户确认/支持流程或物理灾难恢复，因此生产恢复 Gate 继续 `hold`。

## 未关闭 Gate

- 用户自有存储或 E2EE 路线、recovery secret 建立/轮换/遗失、换机与退出迁移尚未获批和实现。
- 双端普通用户仍看不到备份健康、候选详情、明确切换、cleanup/support 状态；在生产路线获批前
  不提前暴露同安装内核，避免把设备 key 尚在误导为灾难恢复。
- Android 新激活 instrumentation 已在独占 API 36 / 16 KB AVD 执行；物理设备仍未执行。
  iOS failure injection XCTest 尚未在完整 Xcode 执行。
- 真实进程 kill、断电、磁盘满、rename/cleanup 错误、文件保护、OEM 文件系统与大媒体恢复尚未演练。
- 真实用户、T0 Pilot、双端物理设备/读屏、签名、商店、安全/发布负责人签收继续 `hold`。

## 判定

`P0-LOCAL-RECOVERY-ACTIVATION-MOBILE-05` 关闭了仓库内“隔离候选没有安全 live-store 切换、
中途失败没有回旧库、重启无法判断 commit”的实现空白，结论为 `conditional_pass`。不得将本报告
扩写为用户可见生产恢复、跨设备 key recovery、物理恢复演练或封闭 Beta 已通过。
