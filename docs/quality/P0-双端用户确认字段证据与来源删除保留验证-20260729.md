# P0 双端用户确认字段证据与来源删除保留验证

## 结论

仓库内“来源删除后只有 source evidence，没有独立用户确认依据”的 P0 缺口已收敛为双端同构的生产规则，Verdict 为 `conditional_pass`：

- 用户确认 provenance 与来源字段证据分表/分模型保存，不用 fact status 或 source link 反推用户动作。
- 记录只含确认 ID、Event ID、精确 revision、确认类型、字段名集合、是否覆盖完整 accepted field set、时间与 terminal state；不保存字段值、标题、正文、用户原话、用户 ID、来源内容或 locator。
- 只有显式接受完整 Coverage Candidate 字段集形成的 `completeFieldSet=true` 记录可以独立支持删源保留。删除唯一来源时仍终结 source link/claim，Event 追加新 revision，来源标签改为“用户确认（来源已删除）”。
- 原 revision 的确认记录只允许 active→deleted；同一显式确认以相同 confirmation ID 携带到新 revision，保留可审计的 exact-revision 链。
- 缺少完整字段集合的 fact-status 确认或用户补充只形成 `partial` 审计记录。它不能保留失去唯一来源的 Event；字段失去最后支持时整 Event 删除。
- Agent `append_revision`、Event/Revision undo 与普通删除只终结旧确认，不创建或升级用户确认。v12→v13、v7→v8 迁移只建立空确认集合，不从旧 fact status、source link 或字段证据猜测用户动作。
- iOS 认证同安装恢复候选保留 envelope 内确认记录；Android SQLCipher snapshot 自然包含 v13 表。删除水位、space root 和旧备份拒绝边界保持不变。

这不是“真实用户已经完成确认”的证据，也不是 account/Grant/Contract 删除、provider 原件删除、peer ack、物理擦除或生产合规删除证明。物理设备、完整 XCTest runtime、真实用户触发面和外部删除 proof 均保持 `hold`。

## 跨端语义矩阵

| 场景 | 允许保留 | 必须动作 |
|---|---|---|
| 显式接受完整 Candidate | 是 | 写 exact-revision complete confirmation；删源时终结来源 claim、追加 Event revision、携带 confirmation |
| 事实状态确认但没有完整字段集合 | 否 | 写 partial 审计；唯一来源删除时删除 Event |
| 用户补充但没有完整字段集合 | 否 | 写 partial `user_revision`；不得把正文补充冒充完整 Candidate 确认 |
| 多来源字段仍获剩余来源支持 | 是 | 依既有 exact-revision field evidence 保守重算 |
| 字段仅由完整用户确认支持 | 是 | 可重算，但来源 link/claim 必须终结 |
| legacy、stale 或冲突字段集合 | 否 | 不回填、不猜测；删除或 `lineage_unavailable` fail closed |
| Agent revision/undo | 否，不形成确认 | 终结旧 revision confirmation，不伪造用户动作 |

## 双端实现与迁移

| 平台 | 实现 |
|---|---|
| Android | schema v13 新增 `event_user_confirmations`、exact-revision 复合主键、current 查询索引、禁止物理删除 trigger 和 terminal-only update trigger。Coverage `UserConfirmed` 写完整 Candidate 字段集；fact/user revision 根据可证明字段集写 complete 或 partial；删源动作把剩余 source fields 与完整确认 fields 合并判断。 |
| iOS | envelope v8 新增 `EventUserConfirmation` 数组与一致性校验：唯一键、active 记录必须绑定当前 Event revision，同 revision 的 active complete 集合必须一致。全部 mutation 有同事务快照/回滚；`LocalBackupStore` 恢复保留确认记录。 |
| 迁移 | Android v12→v13 只建空表并登记 migration；iOS `LegacyLocalStoreEnvelopeV7` 保留既有 field evidence、令 user confirmations 为空并立即重写 v8 密文。两端都禁止猜测 backfill。 |
