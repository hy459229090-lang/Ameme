# P0 双端字段来源证据与多来源删除重算验证

## 结论

仓库内原先“多来源 Event 一律 `lineage_unavailable`”的缺口已经收敛为可执行且保守的生产规则，Verdict 为 `conditional_pass`：

- Candidate 显式接受时可提交 `EvidenceField → Set<SourceObjectID>`。证据记录不保存字段值或正文，只绑定 Event 的精确 revision、字段和来源。
- 单来源 Candidate 可从唯一来源安全派生完整字段映射；多来源 Candidate 必须显式提供与 `observedFields` 完全相等的键集合，值只能引用 Candidate 来源，且每个已链接来源至少支持一个字段。缺项、空集合、未知来源或未覆盖来源都拒绝接受。
- 删除多来源中的一个 source 时，只有精确当前 Event revision 存在完整 active 字段证据，且删除后每个已接受字段仍至少有一个 active source，才追加保守重算 revision。
- 重算保留仍有字段证据支持的 Event 内容，清空来源 locator，来源标签改为通用“多来源（已重算）”，终结旧 revision 字段证据，只把剩余证据复制到新 revision；同时 detach 原 Coverage link 并使 exact-revision 长期 Memory 失效。
- 若任何字段失去最后一个来源，删除整个 Event，而不是保留无法证明的正文；若字段映射缺失、旧 envelope/schema 没有映射，或用户修改已使证据 revision 过期，则整个 source cascade 返回 `lineage_unavailable` 且不修改 source/Event。
- 删除结果和审计记录分别写入 `affectedEventCount`、`recomputedEventCount` 与 `deletedEventCount`，并拒绝分项合计超过受影响 Event 数。

该规则不声称用户确认字段可在来源删除后自动保留；用户 revision 会主动终结旧字段证据。它也不等于 account/Grant/Contract 删除、provider 原件删除、peer ack、物理擦除或真实用户/设备验证。

## 保留 Gate

- Android schema v12 instrumentation 尚未在 AVD 或物理设备执行；WAL、迁移、trigger、故障注入和进程终止仍需独占设备证据。
- iOS v6→v7 migration 与新 XCTest 尚未在完整 Xcode/真机执行；File Protection、磁盘满和进程强杀仍待验证。
- 当前字段证据来自明确 Candidate acceptance，不是自动内容分析或 provider 级 field lineage；legacy 多来源不会被猜测回填。
- 用户独立确认内容的长期保留策略尚未形成单独 provenance；用户 revision 一律使旧字段证据 stale。
- account/Grant/Contract、provider 原件、peer/云副本、用户自有或 E2EE 跨设备恢复和物理擦除继续 `hold`。
- T0 8×7、真实用户 outcome、双端物理设备/读屏、真实 Agent、生产恢复、签名/商店、成本与事故回滚继续 `hold`。
