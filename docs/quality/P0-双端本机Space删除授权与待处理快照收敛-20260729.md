# P0 双端本机 Space 删除授权与待处理快照收敛

## 结论

双端产品入口现已在既有 Personal space 根删除水位之上，补齐“当前安装删除后仍保留本机 Agent 入口、连接元数据或待处理分享/导出快照”的仓库内缺口，Verdict 为 `conditional_pass`：

- Android 与 iOS 设置页都要求用户逐字输入 `删除` 后才启用破坏性动作，并把终态、部分失败和重试状态区分展示。这个入口是“删除本机 Personal 空间”，不是账号注销或全局权利请求。
- 收敛协调器把每一项结果保存为不含正文的 step ID，只在全部本机步骤完成时返回 `completed_local_only`；任一步失败都返回 `pending_local_retry`，外部 provider cleanup 未完成则返回 `pending_external_cleanup`。双端结果硬编码拒绝账号删除、共享 Grant registry 撤销、peer 删除证明、provider 原件删除、物理擦除和设备执行宣称。
- Android 会停止并等待当前 Local Node worker 退出、冻结本机 space、验证清除当前安装的 pairing/Grant secret、关闭 outgoing transport、清除连接展示元数据，并清空且冻结 Keystore 加密 pending-action 快照。配对撤销会验证 SharedPreferences、`pairing.json` 及临时文件均已消失。
- iOS 会关闭当前活跃 Agent transport、冻结本机 space、验证清除连接元数据，并清空且冻结加密待导出快照和 App Group incoming-share handoff。Share Extension 在删除水位存在后拒绝写入新 handoff，避免主 App 重启后复活已删除空间的数据入口。
- 两端删除标记都只保存 content-free 固定水位；清理会覆盖已知文件、隐藏文件、孤儿临时文件和旧格式残留。水位落盘后，后续 load/save 或 Share Extension handoff 写入 fail closed。

这里的“授权收敛”严格限定为当前安装内已持久化的 pairing、secret、运行时与连接元数据。它不代表账户身份服务或共享 Grant registry 已撤销，也没有证明其他设备、离线 peer、云副本、用户已分享外部副本或 provider 原件已删除。

## 产品与执行语义

| 层级 | 成功条件 | 失败行为 | 不包含 |
|---|---|---|---|
| Personal space root | Repository 原子终结可读投影并写不可回退 SPACE 水位 | 普通读写持续冻结；本机 cleanup 可重试 | account、peer、provider 原件、物理擦除 |
| 当前安装 Agent | runtime 已停止且 worker 已退出；本机 pairing/secret、outgoing transport 和连接元数据已清除 | 保持 space 冻结，返回 `pending_local_retry`，启动时继续收敛 | 共享 Grant registry、远端 revoke ack、真实 Host 证明 |
| 待处理动作 | Android pending action、iOS pending export 与 incoming-share handoff 已清空且写入防复活 marker | 已成功步骤不回退；未完成 step 保留为可重试状态 | 系统 Share Sheet 外部副本、provider 原件 |
| 外部清理 | app-owned payload 或 locator cleanup 已完成 | 返回 `pending_external_cleanup`，不把本机完成扩写成外部删除 | Photos、云端、peer、物理介质 |

删除开始后 UI 中的 `localSpaceDeleted` 状态保持单调：即使后续某个本机清理步骤失败，也不会把空间重新显示为可用。Android 的 `closeAndAwait` 最多等待 5 秒确认唯一 worker 终止；未确认退出时该 step 失败而不是仅调用 `close()` 就声称已停止。iOS root freeze 若失败，协调器仍会尝试清空 pending payload，但不会把 resurrection freeze 误报为完成。
