# P0 双端生产长期 Memory 边界验证

## 结论

Android 与 iOS 生产存储现已具备独立于 Event/Coverage 的长期 Memory 最小对象，类型与 Agent policy 对齐为 `fact`、`decision`、`commitment`、`insight`、`preference`、`relationship`、`health`、`financial`、`major_decision`。编译器输入只能引用当前加密库中一个精确 Event revision，evidence 与 sensitivity 由存储层读取，调用方不能伪造。

所有编译结果都是候选：普通、非推断事实最多进入 `eligible_for_memory_compiler`；推断、Restricted 证据及偏好/关系/健康/财务/重大决定进入 `candidate_user_confirmation_required`。两者都只有显式用户确认后才能成为 `active`。有效期只影响默认可见性，不提高事实置信度；显式 replacement 会把旧 Memory 置为 `superseded`。上游 Event 任一 revision 变化或删除都会在同一生产写入中保守置为 `invalidated`，重编译同一旧 Event revision 只返回终态记录，不会复活或重新确认。

Android Agent Local Node 仍严格保持 Event-only，没有长期 Memory operation，也没有获得 `LongTermMemoryRepository`。本切片不实现自动提取、Agent 自动确认、Memory FTS/embedding、ContextPack recall、跨设备同步或 UI，因此不能扩写成完整“用得上”、生产恢复或真实用户闭环。

## 实现证据

| 平台/层 | 生产实现 | 已建立的不变量 |
|---|---|---|
| Android | `data/LongTermMemoryRepository.kt`、`data/local/LocalLongTermMemoryPersistence.kt`、`LocalEventDatabase.kt` schema v8 | current + append-only revisions + exact Event dependency；确认/替代/失效同 SQLCipher transaction；不写 Event FTS 或 DayLedger |
| iOS | `Shared/LongTermMemory.swift`、`LocalMemoryStore.swift` envelope v3 | Memory 与 Event/Coverage/link 同一 AES-GCM envelope；有序 Memory revision history；v2 显式 decoder；无效 evidence/supersession/future schema fail closed |
| 确认边界 | `eligible_for_memory_compiler`、`candidate_user_confirmation_required` → explicit confirmation → `active` | 候选状态都不是已确认 Memory；敏感类型与推断永不自动 active |
| 有效期与替代 | `validFrom` / `validUntil`、`superseded` | 过期只从默认可见集移除；旧记录保留审计且不回拨 active |
| 上游变化 | `event_revision_changed`、`event_deleted` | 关联候选/active Memory 变为 `invalidated`；reload/recompile 不复活 |
| Agent | 既有 `MemoryRepositoryAgentLocalNodeEndpoint` | 继续只支持 `create_event`；未增加长期 Memory 操作、Grant 或协议声明 |

## 判定

`P0-LONG-TERM-MEMORY-MOBILE-03` 关闭了仓库内“Event 与已确认长期 Memory 没有生产隔离、无法绑定 evidence revision 或上游变化后可能继续可见”的核心缺口，当前结论为 `conditional_pass`。不得将本报告扩写为设备数据库迁移、自动 Agent Memory、真实复用、生产恢复、物理设备或封闭 Beta 已通过。
