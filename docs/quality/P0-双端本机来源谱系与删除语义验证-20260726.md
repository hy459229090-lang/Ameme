# P0 双端本机来源谱系与删除语义验证

## 结论

仓库内“Event 删除之外没有生产 source identity/cascade，Raw-only 容易被误报为已删系统原件”的缺口已收敛到可执行的本机生产边界，Verdict 为 `conditional_pass`：

- Android schema v11 新增 `source_objects`、`event_source_links` 和 append-only `deletion_jobs`。新来源捕获与 Coverage Candidate 接受都会写 source→Event link；完整单来源 cascade 在同一 SQLCipher transaction 中 tombstone Event、detach Coverage link、invalidate Event-bound long-term Memory、关闭 open Candidate、终结 source/link 并写不可回退 source watermark。
- Android 的 source/link terminal trigger 同时锁定 `space_id`、`source_object_id` 与 `event_id` identity，不能借 active→deleted transition 改写主键谱系；直接 SQL identity rewrite 用例已进入 instrumentation。
- Android 当前没有应用自有 Raw Vault。`raw_only` 对 provider/content locator 只返回 `external_not_owned`，对无 Raw 的 Coverage evidence 返回 `no_raw`；不会把 ContentResolver locator 或系统原件写成已物理删除。
- iOS envelope v6 新增 `SourceObject`、`EventSourceLink` 和不含正文的 `SourceDeletionRecord`。应用自有 AES-GCM 媒体执行两阶段 Raw-only：先持久化 `pending_cleanup` 并移除 Event locator/追加 revision，再真实删除 app-private ciphertext，最后持久化 `deleted`；重启会重试 pending cleanup，备份在 pending 期间 fail closed。
- iOS Photos 等外部 locator 的 Raw-only 返回 `external_not_owned`；外部 source cascade 明确返回 `completed_local_only`，只终结本机 Event/lineage，保留且不宣称删除系统原件。Android 使用相同的 local-only terminal status。
- iOS 同安装备份现在以 app-owned `SourceObject` 的 locator/digest 为权威媒体清单，Event locator 只用于 legacy 兼容；available/pending Raw 必须具有合法本机密文 locator，备份校验与恢复拒绝缺失 manifest entry、错误 digest 或旧绝对路径。单来源 cascade 事务化收敛 Event、Coverage、long-term Memory、source tombstone 和 lineage；旧快照/重新编译不能越过 source watermark。
- 两端遇到多来源 Event 时，在尚无字段级 provenance/recompute 之前返回 `lineage_unavailable` 且零结构化 mutation；不猜测哪些正文或确认字段可以保留。

这不是 account/space delete、provider 原件删除、跨设备传播、peer ack、合规删除证明或物理设备通过。
