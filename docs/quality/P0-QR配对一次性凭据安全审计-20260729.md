# P0 QR 配对一次性凭据安全审计

> 文档状态：历史发现记录。本文的 v1 `hold` 结论促成了后续 v2 实现；当前仓库实现与验证结论见 `P0-QR一次性Bootstrap与设备凭据轮换验证-20260729.md`。物理设备、共享 Grant 和发布 Gate 仍未因此关闭。

## 结论

现有 `ameme-pairing-v1` 已有跨端逐字一致的 canonical envelope、5 分钟展示/解析窗口、32 字节 secret、TLS 1.3 certificate pin、双向 HMAC、iOS 相机扫描与手动粘贴 fallback，也已有 Swift Network.framework→Android Local Node 的 AVD 纵向 Smoke。它仍不能被称为“服务端强制的一次性 QR 配对”，本 Gate 为 `hold`：

- Android `AgentPairingManager` 为 30 天 pairing 生成并持久化一个 secret；QR envelope 暴露的是同一个 secret，而不是独立的一次性 bootstrap credential。
- Android `AgentLocalNodeRuntime.serveLoop()` 在 pairing 未过期时重复创建单连接 listener，每次仍传入同一个持久 secret。单个 listener 只接受一次连接，并不等于该 secret 在服务端消费一次。
- iOS `PendingAgentPairingRegistry.take()` 只会在当前 App 进程内消费一次扫描结果；这不能阻止已经复制 secret 的其他客户端跳过 QR parser 的 5 分钟时效后直接完成通道握手。
- Android 普通用户入口当前可以生成/展示二维码并提供复制 fallback，但 Release connector 仍 fail closed，也没有 Android 相机扫描→生产客户端 transport 的对称闭环。

因此，当前 5 分钟是 envelope parser 与 UI material 的时效边界，不是 Android 服务端的不可重放证明。现有 AVD/ADB-forward Smoke 证明 frozen v1 transport 可以建立受限连接，不证明真实扫码、server-enforced one-time、进程重启后安全重连、共享 Grant registry 或物理 LAN。

## 首次发现与风险

审查最初按“补 Android 相机扫描入口”的简单模块评估。沿生产连接路径继续追踪后发现，新增 scanner 只会得到现有长期 secret，且 Android Release 没有对应 production client transport；这既不能形成真实连接，也会放大“5 分钟 one-time”误读。

若攻击者在 QR 可见期间复制 secret，客户端 parser 的过期检查不是服务端安全边界。只要 30 天 pairing 仍有效且 runtime 可达，当前协议没有独立 bootstrap nonce 的服务端 consumed ledger，也没有设备公钥绑定或首次连接后凭据轮换来证明旧 QR secret 已失效。风险影响认证材料重放，不涉及本次审查读取或保存真实用户正文。

## 需要的架构决策

推荐采用 `v2` bootstrap 模型：

1. QR 只携带最长 5 分钟、服务端持久登记且原子消费的 bootstrap ID/secret。
2. 客户端同时提交设备公钥；服务端首次成功握手后把 30 天最小 Grant credential 绑定到该设备身份。
3. 服务端在同一事务中消费 bootstrap 并签发/轮换长期 credential；崩溃、网络重试与重复请求必须有 bounded idempotency，旧 bootstrap 不得恢复可用。
4. iOS Keychain / Android Keystore 只保存轮换后的长期 credential；断开、撤销、Space 删除和过期清理要复用现有本机收敛协调器。
5. `v1` 不再对 Release 宣称 one-time；迁移期是 fail closed、明确重新配对，还是仅保留开发 Smoke，需产品/安全负责人拍板。

较小但会牺牲重连的替代方案是把整个 pairing 与 listener 都限制为 5 分钟且首连后关闭；该方案不能满足当前 30 天授权与进程重启重连目标。不能仅靠 iOS 本进程 `take()`、二维码 UI 隐藏、parser 过期或单连接 listener 代替服务端消费。

## 保留 Gate

- 需要先确定“服务端一次性 bootstrap + 30 天设备绑定 credential”还是“5 分钟不可重连 session”；两者会改变协议、持久化、撤销和迁移模型。
- 完整实现需协议版本、Android server credential registry、iOS/Android client secure storage、原子消费/idempotency、迁移与撤销测试；这不是单独增加扫码 UI 的简单模块。
- Android 相机扫描还需要真实 production client transport；若产品仍以 Android 作为 Local Node host、iOS 作为 client，应明确非对称产品边界，不应为了表面对称接入无可用下游的 scanner。
- 两台物理设备上的 QR 泄露窗口、重复扫描、并发首连、过期、重启、后台、撤销、离线与真实 LAN 仍为不可替代外部证据。

## Verdict

`P0-QR-ONE-TIME-BOOTSTRAP-SECURITY-10` 将现有 5 分钟 envelope 与真正 server-enforced one-time credential 明确分离。在凭据模型完成决策、实现和物理设备验证前，真实 QR 配对安全闭环保持 `hold`；不得把静态 34/34、iOS 相机 UI、二维码输出或 AVD/ADB-forward transport Smoke 写成该 Gate 已通过。
