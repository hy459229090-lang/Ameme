# P0 双端本机 Space 冻结与删除水位验证

## 结论

双端生产存储已经具备“删除当前安装内 Personal space 后不可继续读取、写入或从旧备份复活”的最小执行闭环，Verdict 为 `conditional_pass`：

- Android 在一个 SQLCipher transaction 内 tombstone 当前 space 的 active Event、终结 open Coverage Candidate、detach active Coverage link、使 Event-bound 长期 Memory 和复用投影不可读、终结 active SourceObject，并在依赖收敛之后最后写入 `SPACE/space_personal` 根删除水位。根水位存在后普通 Repository 写入 fail closed。
- Android 的 provider/content locator 仍按既有两阶段协调器释放；根水位不会阻断 cleanup coordinator。状态因此区分 `completed_local_only`、`pending_external_cleanup` 和 `already_deleted`，不会把 locator release 写成系统 provider 原件删除。
- iOS 在一次 AES-GCM envelope 提交中清空 Event/Coverage/长期 Memory/复用可读投影，终结 SourceObject/EventSourceLink，写 Event/source tombstone，并在最后写入 `SPACE/space_personal` 根 tombstone。app-owned Raw 先进入 `pending_cleanup`，提交后真实删除应用私有 ciphertext，再持久化完成；外部 Photos 原件不变。
- 双端根水位在加密重载后仍冻结读取和写入。Android 的旧 SQLCipher snapshot、iOS 的旧 AES-GCM artifact 都必须与当前权威水位比较，缺少根水位即拒绝恢复；候选目录不会部分落地。
- iOS 恢复入口会把调用方附加水位与 live store 权威水位合并，调用方不能通过传空数组削弱根水位。删除后的 artifact 仍可做只读认证验证，但创建新备份被禁止。
- Android 根水位写入失败用例验证事务必须回滚全部内存/数据库投影；iOS 持久化故障用例验证 envelope 提交失败后恢复原投影并进入可重试错误态。这两类平台测试源码已进入生成工程/编译门，但当前没有宣称设备或 XCTest 执行。
- `LocalSpaceDeletionResult` 在双端硬性拒绝 `accountDeletionClaim=true` 或 `peerDeletionProofClaim=true`；静态 Gate 也固定输出 Grant、provider 原件、物理擦除和设备执行均未通过。

这里的“删除”是当前安装内加密业务状态的逻辑终结、可读投影收敛和应用自有 Raw cleanup。为防复活与审计而保留的不含正文 tombstone、删除记录、旧 Event revision/SQL 行不构成物理扇区擦除证明；它也不等于账号注销、Grant/Contract 撤销、peer ack、云副本删除或合规权利请求完成。

## 双端实现

| 平台 | 原子边界 | 根水位后的行为 | 后续清理 |
|---|---|---|---|
| Android | `deleteLocalSpace` 使用 `inTransaction(allowDeletedSpace=true)`；根水位最后写入 | Event/Coverage/Memory/复用读取为空，普通写事务由 `requireLocalSpaceActive` 拒绝，旧备份 verify/restore 拒绝 | `markSourceLocatorReleased` 仍可在根水位后完成 persisted URI grant 清理；系统原件保留 |
| iOS | `deleteLocalSpace` 先构造完整终态 envelope，再允许一次根水位提交；失败恢复全部数组 | `storageState=.deleted`，记录、备份创建和其他普通持久化被冻结，重载后保持 deleted | app-owned Raw cleanup 可在根水位后重试；外部 locator 从 Ameme 状态移除，但 Photos/provider 原件保留 |

两端都复用 v11/v6 引入的通用删除水位结构；后续字段来源证据切片把当前版本推进到 Android schema v12 / iOS envelope v7，但没有改变 SPACE root 的语义。该切片已在当前版本重新通过构建、Smoke 与静态 Gate。
