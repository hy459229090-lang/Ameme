# R0 用户任务与竞品证据

> 文档状态：桌面研究完成，真实用户验证未完成\
> 研究日期：2026-07-13\
> 证据边界：官方产品、平台和帮助文档只能证明产品能力、在售方案与产品方选择，不能替代用户访谈、留存或付费数据。

## 1. 当前结论

1. 首个切口应围绕一个可被立即验证的用户任务，而不是“采集所有生活”。当前最清晰的三个任务是：工作上下文复用、会议承诺找回、生活片段回顾。
2. 市场上已经存在为“无限历史、跨会议问答、集成、MCP/API”付费的方案，说明专业用户愿意为可复用的上下文付费；但这不能直接证明 Ameme 的价格或留存。
3. 生活记录产品长期强调多媒体、回顾、数据所有权、加密和导出，说明“回忆”和“控制”必须同时成为体验，不应只做自动摘要。
4. 全屏、全音频、持续采集不适合作为 Ameme 首发默认能力。Limitless 被 Meta 收购后停止向新用户销售 Pendant，Rewind 停止屏幕与音频采集，并在多个地区停止服务。这是持续经营、区域、同意和信任风险的真实反例。
5. Apple Journaling Suggestions 给出了更可信的“半无感”范式：系统发现候选生活事件，但只有用户选中的高层信息才交给应用。Ameme 应优先研究“系统建议 + 一次确认”，而不是把无感等同于后台全量读取。

## 2. 三类核心任务证据

| 用户任务 | 当前市场证据 | 能说明什么 | 不能说明什么 | R0 要验证 |
|---|---|---|---|---|
| 工作/会议上下文复用 | Granola 将会前简报、会中笔记增强、会后行动项、跨会议问答、MCP/API 组合在同一产品中；Business 为每用户每月 14 美元 | 专业用户场景能够围绕“过去上下文直接参与下一步工作”形成付费包装 | Ameme 应复制会议产品；中国用户愿付同价；屏幕活动同样有价值 | 用户真正找不到的是会议内容、项目决策、文件还是 AI 对话；ContextPack 是否比日报更高频 |
| 长期生活回顾 | Day One 提供文字、照片、视频、音频、跨端、往年今日、端到端加密和导出 | 回顾、长期资产和数据所有权构成一组完整价值 | 普通用户愿意接受自动采集；AI 洞察能提升留存 | 用户是否愿意每天确认；最重要的是当天卡片、往年今日、家庭共享还是搜索 |
| 低摩擦生活事件建议 | Apple Journaling Suggestions 汇总地点、联系人、照片、音乐等候选，但应用只有在用户选择后获得所选建议 | 低摩擦和隐私可以同时成立；候选生成与正式保存应分层 | Android 有完全等价能力；中国区数据类型和覆盖稳定 | 一次选择是否足够轻；用户是否理解“建议未进入 Ameme，选择后才进入” |
| 全量数字记忆 | Limitless/Rewind 曾采用屏幕、音频与硬件路线，但 2025 年末后停止新售硬件并关闭 Rewind 捕获 | 技术可行不代表产品可持续；高权限采集具有平台、区域、信任和商业风险 | 任何持续采集都会失败 | 元数据、专用 Connector 和一键 Capture 能否达到“最小充分上下文” |
| Agent 使用个人历史 | Granola 把 MCP/API 放入付费档；MCP 规范定义 Resources/Tools，并要求用户明确同意数据访问 | Agent 接口可能是高价值使用端；权限、purpose 和最小上下文应成为接口契约 | MCP 本身能解决采集、分类、存储与记忆质量 | 用户会在哪些真实 Agent 任务中调用历史；多少上下文才有用且不会泄露其他空间 |

## 3. 对 Ameme 的产品含义

### 3.1 价值链需要完整闭环

只有采集没有使用，用户只会感到被监控；只有日报没有证据，用户不会信任；只有搜索没有主动价值，使用频率会下降。候选闭环至少需要：

```text
一个明确来源
  -> 可解释的事件/片段
  -> 用户低成本确认或纠错
  -> 一个可立即完成的任务
  -> 可查看来源、撤回和删除
```

### 3.2 “无感”拆成四个等级

| 等级 | 交互 | 适用内容 | 首版判断 |
|---|---|---|---|
| L0 自动元数据 | 安装、选范围后后台运行 | 应用切换、选定目录事件、Git 事实 | 可研究，必须可暂停和排除 |
| L1 系统候选 + 一次选择 | 系统先建议，用户选中 | iOS 生活事件、照片、文件 | 优先研究 |
| L2 一键 Capture | 快捷键、分享菜单、浏览器按钮 | 当前网页、截图、文件、用户一句话 | 优先研究 |
| L3 显式会话采集 | 每次开始时确认 | 会议音频、屏幕、敏感正文 | 仅限清晰场景，不作默认 |

“完全无操作的正文/音频持续采集”不作为当前等级，而作为需要独立商业、隐私和合规论证的远期能力。

## 4. 付费假设

当前只能形成待验证假设：

- 专业用户更可能为“节省复述上下文、找回承诺、直接给 Agent 使用”付费，而不是为存储 event 数量付费。
- 普通用户更可能理解“历史长度、同步、空间数量、每日/每周回顾”，不适合暴露 token 计费。
- API/MCP、组织控制、保留策略和审计可以进入高阶方案，但在核心价值未验证前不设计完整套餐。
- 访谈必须询问用户当前已付费的替代品、实际取消原因和最近一次付费决策，避免只问“你愿意付多少钱”。

## 5. 否决信号

出现任一情况时，不应把对应场景推进为 MVP：

1. 用户只能表达抽象兴趣，无法提供最近 14 天内的具体丢失/复述/回顾事件。
2. 输出看起来“很酷”，但不能改变下一步行为，也不会在三天内再次使用。
3. 必须先获得全盘、全站或全聊天权限才能提供第一价值。
4. 用户无法理解暂停、排除、空间和删除传播的区别。
5. 需要处理他人内容，却没有可执行的告知、同意和组织授权路径。
