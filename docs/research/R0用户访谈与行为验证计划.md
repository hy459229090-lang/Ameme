# R0 用户访谈与行为验证计划

> 文档状态：等待招募确认\
> 目标：用近期真实事件、现有替代方案和小型行为实验，判断首个重点用户与任务。\
> 非目标：用访谈证明技术可行、让参与者替团队设计功能、直接确定价格。

## 1. 样本结构

在正式招募前，用产品负责人本人和 FORMALdoc 工作区校准专业桌面来源，但它不代表产品主链。另准备一个不含 Git/工作区的通用一天样本，验证照片/分享/日历/一句话能否进入同一种 DayLedger。两者都不计入下面 15 人的用户证据，也不能用于推断市场需求。

第一轮共 15 人，三个对比组各 5 人：

| 组 | 入选条件 | 重点任务 |
|---|---|---|
| A：AI Native 知识工作者 | 每周至少 3 天使用 Coding Agent/ChatGPT/Claude/Codex 等；同时处理网页、文件或代码 | 项目进展、决策找回、历史经验复用、Agent ContextPack |
| B：沟通密集专业用户 | 每周至少 8 场会议或高频客户/跨团队沟通 | 承诺、人物背景、行动项、会前准备和跟进 |
| C：移动生活记录用户 | 经常拍照/截图/记录运动、旅行、消费或家庭事件；过去尝试过记录 | 低摩擦 Capture、每日确认、长期回顾和空间隔离 |

执行顺序：先做每组 1 人的 3 场试访，修订问题后完成其余 12 场。不要用 15 人的比例推断总体市场规模。

## 2. 招募筛选

招募时只问事实：

1. 最近两周使用了哪些 AI、日记、会议记录、笔记或自我量化工具？
2. 最近一周会议数量、主要工作端和主要生活记录端是什么？
3. 最近一次“明明发生/做过但找不到”的事情是什么时候？
4. 是否愿意在访谈中展示一份已脱敏的现有记录或复盘流程？
5. 是否愿意参加 3 天、每天不超过 3 分钟的行为实验？

排除：只表达概念兴趣、没有近期事件，也不愿展示任何现有流程的样本，不进入首轮核心样本。

## 3. 45 分钟访谈结构

### 0–5 分钟：边界

- 明确不要求展示聊天正文、客户数据、健康/财务原始数据。
- 参与者可随时跳过问题；研究记录只保存脱敏结论和引用编号。

### 5–20 分钟：最近一次具体事件

围绕一件最近 14 天发生的事追问：

1. 当时想找回或记录什么？
2. 信息最初出现在哪个端、哪个应用、什么形式？
3. 什么时候意识到找不到/忘记/需要再次复述？
4. 最后怎么解决？花了多少时间？造成了什么后果？
5. 如果系统当时给出一个候选记录，哪一步必须由本人确认？

禁止用“你平时会不会……”代替事件追问。

### 20–32 分钟：现有替代流程

- 请参与者演示脱敏后的搜索、笔记、日历、照片、日报或 Agent 上下文流程。
- 记录触发点、步骤、耗时、放弃点、跨端搬运和重复输入。
- 询问已经付费的工具、为什么续费/取消，而不是直接问理想价格。

### 32–40 分钟：权限阶梯测试

依次展示四档能力，每次只改变一个变量：

1. 一键分享当前内容。
2. 选定应用/目录的元数据。
3. 选定来源的正文或音频。
4. 跨空间/跨端云同步和 Agent 调用。

每档都要说明：采集什么、不采集什么、保留多久、在哪里处理、如何暂停与删除。记录参与者的接受/拒绝理由，不诱导其同意。

### 40–45 分钟：任务排序

让参与者在以下结果中只选前两项，并说明放弃其他项的原因：

- 今天发生了什么。
- 找回某个事实或原对象。
- 生成周报/项目回顾。
- 提醒承诺和下一步。
- 给 AI 提供历史上下文。
- 看懂长期变化。

## 4. 三天行为实验

从每组选择 2 人，共 6 人。研究者以 Wizard-of-Oz 方式提供候选结果，不接触未授权原文。

每天：

1. 参与者通过一键分享或合成模板提交 1–5 个对象。
2. 研究者生成一个带来源引用的 Timeline/Brief/ContextPack 候选。
3. 参与者先按时间线补漏、修改或删除事件，再对重要事件补充重要性、空间或“无用”反馈；不要求其理解记忆类型，记录耗时。
4. 第三天要求参与者用历史结果完成一次真实任务。

记录：提交次数、事件遗漏、时间错序、描述修正、错误合并、规则复用、确认耗时、主动找回、实际使用结果、删除预期和第 3 天继续意愿。详细反馈动作与指标见 `../product/记忆反馈与类型覆盖框架.md`。

## 5. Gate 1 判定规则

以下是进入 Prototype 的最低证据，不代表市场已经验证：

| 条件 | 通过标准 |
|---|---|
| 近期问题成立 | 某一组至少 3/5 能提供最近 14 天的具体事件，并存在可观察成本或当前替代流程 |
| 首要任务收敛 | 同组至少 3/5 把同一结果排在前两位，且理由来自近期事件 |
| 最小权限可接受 | 同组至少 3/5 接受候选 Prototype 所需的精确权限，并能复述暂停/排除/删除方式 |
| 行为价值 | 对应组行为实验参与者均完成三天，且至少 1 人主动用历史结果完成真实任务 |
| 确认负担 | 每日确认中位数不超过 2 分钟；高风险错误必须可以在保存前发现 |
| 数据边界 | 不依赖无法授权的他人数据、全量聊天、全盘或隐藏采集才能成立 |

若三个方向均不满足，Gate 1 应保持 `hold`，回到用户任务而不是扩大采集范围。

## 6. 研究记录模板

每位参与者只保存：

```text
participant_id:
segment:
recent_incident:
source_and_device:
current_workaround:
observable_cost:
top_tasks:
accepted_permission_level:
rejected_permission_and_reason:
deletion_expectation:
paid_alternatives:
confirmed_events:
missing_time_ranges:
event_description_corrections:
important_missing_event:
future_capture_rule:
contextpack_use_result:
evidence_quotes_redacted:
researcher_inference:
open_questions:
```

事实、原话和研究者推断必须分栏；不把参与者提供的样本正文提交到 Git。
