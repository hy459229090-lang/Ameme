# Ameme Agent Skill 产品与交互规格 v0.2

> 文档状态：已接受；MVP 研发前正本\
> 更新日期：2026-07-15\
> 适用范围：Codex、Claude Code、Cursor 等支持 MCP/Skill 的 Agent 宿主\
> 产品包正本：`../../packages/agent-skills/ameme-memory/`

## 1. 产品判断

MVP 只向用户暴露一个 `Ameme Memory` Skill。配对、召回、任务上下文、写回、纠正和状态是同一记忆能力的六种模式，不拆成一组需要用户学习的命令。

Skill 是 AI 使用者的主战场之一，但不是新的桌面管理端。宿主 Agent 负责当前任务交互，Ameme Mobile/Web 负责查看、补充、授权、来源、删除和完整审计。

## 2. 核心任务

| 任务 | 用户表达示例 | 模式 | 结果 |
|---|---|---|---|
| 连接 | “把这个 Agent 连到 Ameme” | `ameme.pair` | 展示范围并完成配对 |
| 显式记住 | “记住这次评审决定” | `ameme.capture` | 直接写入带证据和撤销的长期记忆 |
| 显式召回 | “上次为什么这样设计？” | `ameme.recall` | 返回带范围/完整性的历史 |
| 任务上下文 | 当前任务需要既往方案 | `ameme.context` | 最小 ContextPack 注入 |
| 任务结束写回 | 已执行并有证据的结果 | `ameme.capture` | `autonomous_memory` 授权内自动写入 Event/Revision |
| 纠正 | “这条记错了” | `ameme.feedback` | 新增纠正/拒绝事件 |
| 状态 | “Ameme 同步好了吗？” | `ameme.status` | 返回可恢复的语义状态 |

删除、导出和恢复属于高影响产品流程，不伪装成普通 Skill 写入操作。

## 3. 低摩擦与可见性

- 普通用户在 Mobile 通过同网发现、扫码或账户设备找到 Agent；三种入口共享同一 Mobile 授权页。宿主可以发起/展示候选，但不能替 Mobile 代为批准。
- Skill 不要求普通用户复制长期密钥、JSON、IP 或端口。用于工程验证的手工 TLS 凭据只属于 Debug 开发者路径，不能成为公开产品教程。
- 第一次配对、新宿主、新空间、Restricted/Raw、外部处理、导出、恢复和删除必须显式确认。
- 已有精确 `autonomous_memory` 授权时，Agent 可自动取最小上下文并直接写入长期 Event/Revision；每次写入在活动记录中可见、可撤销、可纠正。
- 每次召回都能说明空间、时间范围和 `complete/partial/unknown`；无结果不等于“用户没有做事”。
- 记忆能力失败不阻塞 Agent 主任务；离线写回标记为“本地排队”，不能写成“已同步”。

## 4. 默认授权

默认 Grant 仅包含一个宿主调用方、一个空间、明确目的（含 `autonomous_memory`）、Structured 数据和 30 天有效期。默认隐式上下文取最近 30 天、最多 12 项、宿主渲染 2,000 token；ContextPack 15 分钟过期。首次授权仍明确展示自动读写后果。

Raw 和 Restricted 数据默认不进入宿主上下文。情绪/关系是独立记忆维度，不能因为“很重要”就提高事件事实置信度或绕过权限。

## 5. 状态与反馈

用户可区分：`未连接`、`等待确认`、`可用`、`结果不完整`、`离线`、`拒绝`、`已撤销`、`已过期`、`服务错误`。所有失败提供最小恢复动作，不反复弹授权。

记忆纠正采用追加式反馈/Revision：保留原始证据、用户纠正和重算结果。疑似提示词注入属于安全反馈，可阻断相关内容进入后续 ContextPack。

## 6. 验收标准

1. 六种模式均有唯一主工具和稳定状态。
2. 未配对、越权、过期、撤权、离线、部分覆盖和注入样本均有自动评测。
3. 当前用户指令始终高于记忆内容；记忆正文不能扩大工具权限。
4. 一次失败重试不重复写入；自动 capture 有幂等键、证据状态、活动记录和撤销。
5. 至少一个真实宿主通过 MCP Mock 完成：配对 → 最小召回 → 有证据写回 → 纠正 → 撤权。
