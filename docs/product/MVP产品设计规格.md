> 文档状态：已接受；MVP 研发前产品正本，真实价值/真机达成待 Gate 证据\
> 更新日期：2026-07-14\
> 适用版本：封闭 MVP 候选\
> 当前边界：本文定义产品价值、范围、规则、指标和验收，不代表 Gate 1/2 已通过或工程已获准开工。

## 1. 产品命题

Ameme 的 MVP 要验证：

> 在用户不持续写日记的情况下，能否利用 Mobile 与既有 Agent 中获准的信息，形成一份清楚、可信、可补充、可搜索并可被后续任务使用的“今天”。

产品基础单位是一天中发生的事件，不是日记文章、原始采集流或 AI 总结。价值顺序固定为：

```text
获得获准来源
 -> 形成可追溯事件
 -> 组织为今天
 -> 用户补充/纠错
 -> 通过搜索按钮按日期或关键词查看历史
 -> 为 Agent 提供最小上下文
 -> 再形成总结和长期记忆
```

## 2. 首批用户与扩展用户

### 首批用户

已经使用 Coding Agent 或通用 Agent 的高信息密度知识工作者，例如产品经理、研发、研究者、创作者和小团队创业者。

共同特征：

- 工作与生活中每天产生大量分散信息。
- 已经在 Codex、Claude Code、Cursor 等 Agent 中留下高价值任务上下文。
- 经常忘记之前做过、决定过、看过或为什么这样选择。
- 能理解早期 MCP/Skill 配对，并愿意反馈权限和记忆质量。

### Mobile 独立用户

不使用 Agent 的普通用户也必须能够仅靠 Mobile 完成：

`授权或主动补充 -> 今天 -> 修改/删除 -> 搜索按钮 -> 日历跳转/关键词筛选`

因此 Mobile 的界面、术语和注册不能以代码、工作区或 MCP 为前提。

### 当前不优先服务

- 需要持续录音、全量屏幕回放或完整聊天监控的用户。
- 需要家庭共享、企业组织管理或医疗诊断的场景。
- 只希望得到情绪陪伴、不关心事件事实和来源的用户；情绪风格后续单独验证。

## 3. MVP 目标与非目标

### 产品目标

1. 覆盖一天中有意义的工作和生活事件，而不是追求原始数据量。
2. 普通一天可以零输入；主动补充只需一次拍摄、分享、上传或一句话。
3. 用户能区分已记录、推测、待核验、冲突、整理中和仅本机。
4. 用户能从 `今天` 右上搜索按钮进入历史日流，通过日历和关键词缩小范围，并知道检索范围是否完整。
5. 在数据不足、来源未授权、未同步或处理失败时仍然可用，只呈现已知事件和明确缺口。
6. Agent 能在用户首次明确授予的 `autonomous_memory` 范围内自动读取最小上下文，并将任务事实直接写成可追溯 Event/Revision；超出范围时再请求确认。
7. 来源、权限、Revision、删除传播和访问审计构成 MVP 信任底座。

### 非目标

- 不在 MVP 提供长期人格画像、跨周人生建议或自动替用户决策。
- 不建设完整 Web App、小程序、Browser Extension 和 Native Desktop。
- 不接入全量 IM、账单、游戏、邮箱和服务 Connector 矩阵。
- 不默认上传完整照片库、原始音频、连续位置轨迹或健康原始流。
- 不冻结云厂商、模型提供方、数据库品牌和跨端共享框架。
- 不在效率版中做工作绩效评分或把生活解释成生产力。

## 4. 产品形态

| 组成 | MVP 职责 | 不承担 |
|---|---|---|
| iOS Native App | 手机来源获取、`今天`、历史搜索、补充、设置和控制；使用 SwiftUI/系统原生控件与平台交互 | 模拟 Android 特有权限、复制 Android UI、完整桌面采集 |
| Android Native App | 同一核心能力；使用 Jetpack Compose Material 3/系统原生能力与平台交互 | 模拟 iOS 系统建议、复制 iOS UI、厂商差异隐藏 |
| Agent MCP/Skill/API | 任务内获取、capture、recall、context、feedback 和写回 | 数据库直连、无限期跨空间授权 |
| Personal Event Core | Event 主链、归并、Revision、DayLedger、RecallQuery、同步、权限和删除 | 强制所有原始数据上传云端 |

MVP 采用效率风格：安静、清楚、可信、紧凑和快速，但不冰冷。情绪风格后续作为同一 Event Core 上的表达层，不复制数据和权限体系。

## 5. 六条核心旅程

### J1：建立第一份真实的今天

```text
理解“自动整理今天”的价值
 -> 选择来源包
 -> 系统分项授权
 -> 立即获得一项真实内容或主动补充
 -> 今天出现第一条可追溯事件
```

成功标准：用户能说清已开启哪些来源、保存在哪里、是否同步，并在拒绝部分权限时继续使用。

### J2：一天中的低负担记录与纠错

```text
获准来源低打扰更新 + Agent 写回
 -> 今天按时间显示事件
 -> 用户上传/说一句/输入补充
 -> 先本地保存，再异步整理
 -> 仅对一个高价值缺口追问
 -> 修改形成 Revision
```

成功标准：用户主动内容不会因 AI 或网络失败丢失；首页不变成采集流水或审核任务列表。

### J3：搜索历史并继续使用

```text
点击 `今天` 右上搜索按钮
 -> 在统一历史日流向上滑加载更早日期
 -> 用日历跳到某日，或用日期范围/关键词筛选同一日流
 -> 获得仍然按日分组、并带范围说明的事件结果
 -> 查看来源或事件详情
 -> 后续由 Agent 复用 RecallQuery 获取最小上下文
 -> 使用结果回写反馈
```

成功标准：本地、同步和未参与设备范围清楚；无结果不被表述为“从未发生”。

### J4：Agent 配对、调用和结果写回

```text
用户在 Agent 发起一次性配对
 -> Mobile 显示调用方、用途、空间、数据类型和有效期
 -> 用户批准或收窄范围
 -> Agent 在任务内 capture/recall/context
 -> Core 返回最小 ContextPack 或明确拒绝原因
 -> Agent 使用结果后提交有用/不相关/缺失/过时/越权反馈
 -> 授权范围内产物直接形成可追溯 Event/Revision，并在 Mobile 可见、可撤销
```

成功标准：未授权、过期、跨空间和超范围请求必须失败且留下不含内容的审计；配对撤销后新请求立即失效，已同步副本按删除/撤权策略处理。

### J5：来源、权限、空间与同步管理

```text
从首次使用、设置或页面缺口进入来源
 -> 看见产品选择与系统权限的差异
 -> 开启、限制、暂停或修复一个来源
 -> 看见影响范围、处理位置和是否同步
 -> 返回原页面并局部刷新
```

成功标准：拒绝、有限授权、无数据、系统限频、读取失败和未同步均有不同状态；修改一个来源不阻塞其他来源和主动补充。

### J6：删除、撤权与导出

```text
从事件详情或设置发起删除/撤权
 -> 查看将影响的来源、Event、DayLedger、Summary、索引和同步副本
 -> 本地先进入不可见/待传播状态
 -> 各副本确认或返回可重试失败
 -> 用户查看最终范围与例外

设置中发起结构化导出
 -> 选择空间和日期范围
 -> 本机生成可移交包
 -> 失败可重试且不改变原数据
```

成功标准：删除失败不能静默；撤权不自动伪装为历史数据已删除；导出不包含未选择空间、未获准原始对象或密钥。

## 6. MVP 能力与优先级

| ID | 能力 | 优先级 | MVP 产品规则 |
|---|---|---:|---|
| ONBOARD-001 | 首次价值与来源选择 | P0 | 不以 Event/MCP 术语开场；允许拒绝权限后直接进入 `今天` |
| TODAY-001 | `今天`事件时间线 | P0 | 事件优先，小结后置，不显示虚假覆盖率 |
| CAPTURE-001 | 语音/照片/文字/导入补充 | P0 | 先本地保存，再异步处理；失败保留原始内容 |
| SOURCE-001 | 照片 | P0 | 用户选择或获准范围；原图默认留来源端 |
| SOURCE-002 | 机会式位置 | P0 | A0–A3 最低成本足够信号；不持续 GPS |
| SOURCE-003 | 日历 | P0 | 计划默认不等于实际发生 |
| SOURCE-004 | 身体与活动 | P0 | 五类授权包；默认推荐活动、锻炼、睡眠；是首个公开版本发布条件，资格/申报/真机门禁未通过时阻断发布，不静默关闭后发布 |
| RECALL-001 | 统一历史日流 | P0 | 向上按日加载更早记录；日历只跳转锚点，不切换结果布局 |
| RECALL-002 | 日历/关键词筛选 | P0 | 与日期取交集；命中结果仍按日分组；显示设备/空间/同步范围 |
| CONTROL-001 | 设置二级入口 | P0 | 来源、权限、空间、同步、Agent 和删除，不占内容导航；按平台原生呈现 |
| TRUST-001 | 来源与状态解释 | P0 | 用户可理解字段依据，不展示工程调试信息 |
| TRUST-002 | Revision 与纠错 | P0 | 追加修订，不覆盖历史和用户原话 |
| TRUST-003 | 删除传播 | P0 | 覆盖事件、DayLedger、Summary、Memory、索引和同步副本 |
| SYNC-001 | LAN 选择性同步 | P0 | 同账户已批准设备在同一 LAN 内点对点同步；原始默认本地；未同步必须在其他端显式；身份服务不保存记忆内容 |
| AGENT-001 | Agent capture/recall/context/feedback | P0 | purpose、space、time、data type、caller、expiry 最小授权；`autonomous_memory` 明确授权后可自动读写 Event/Revision，Restricted/Raw/扩权/删除仍有独立安全门 |
| DEVICE-001 | 设备与同步范围 | P0 | 展示参与设备、最后同步和缺失范围；不把 partial 表述为完整 |
| AUDIT-001 | 访问与高风险操作审计 | P0 | 记录调用方、用途、范围、结果和时间，不记录正文/搜索词/模型输入 |
| EXPORT-001 | 结构化数据导出 | P1 | 按空间和日期生成本机可移交包；不导出密钥和未选择原始对象 |
| SUMMARY-001 | 今日小结 | P1 | 当日事件流末尾显示 2–3 行简版并可展开；只读取事件；数据不足时不生成；事件变化后失效重算 |
| EMOTION-001 | 情绪风格 | 后续 | 另行验证，不进入 MVP 视觉和核心承诺 |

P0 表示产品闭环不可缺；不等于所有 P0 能在同一工程切片一次完成。

## 7. Mobile 来源包产品规则

| 来源包 | 内容 | 用户价值 | 默认策略 |
|---|---|---|---|
| 生活现场 | 照片 + 位置 | 到访、聚会、旅行、餐饮和现场 | 用户选择照片范围；位置渐进授权 |
| 时间安排 | 选定日历 | 会议、计划和时间锚点 | 分日历/时间窗授权，计划不升级为事实 |
| 身体与活动 | 活动、锻炼、睡眠、恢复、正念 | 身体活动和生活背景 | 推荐前三类，恢复/正念同页可选 |
| 工作增强 | Agent MCP/Skill/API | 任务、决定、产物和后续找回 | 主动配对，任务/用途/空间/有效期受控 |

首次路径用一个产品页解释来源包，但系统权限仍逐项申请。相机和麦克风在第一次实际使用时申请，不为以后可能使用提前索取。

## 8. 信任与权限底座

1. 情绪、关系和重要性只影响表达、排序与回顾，不提高任何事件事实字段的置信度。
2. “这件事很重要”只更新 Salience，不触发或绕过空间、来源、同步、处理位置或 Agent 权限；扩权只能从独立具体使用动作发起。
3. 重要性、风格和搜索不能改变空间权限。
4. 用户拒绝、有限授权、近似位置和无后台权限均为可继续使用状态。
5. 不设置面向用户的“最小来源组合”。任意已授权来源和主动补充都可独立进入事件主链；数据稀疏是正常产品状态，不是用户未完成配置。
6. 原始数据按 A 方案保留在来源设备并执行集中 TTL；事件化结果独立保留，SourceLocator 保存不暴露完整路径的本地源索引，用户选定的原始对象才进入已批准 LAN peer 的加密同步。源索引只能帮助重新定位，不能保证源文件未移动、未删除或仍有权限。
7. 没有返回数据必须区分无活动、无授权、未同步、系统限频和读取失败。
8. 所有派生结果能回到来源；删除和撤权能沿 lineage 传播。
9. Restricted 数据默认不上传云模型；具体威胁模型在 Gate 3 前确认。

## 9. 产品指标

指标口径与埋点以 `MVP指标与埋点字典.md` 为正本。本阶段定义指标，不虚构目标阈值：

| 维度 | 指标定义 |
|---|---|
| 覆盖 | 复盘后重要遗漏数、来源独特事件增量、已知缺口时段 |
| 准确 | 误报、错误合并/拆分、时间错序、字段修订次数 |
| 负担 | 每日主动输入次数、完成一次补充步骤、权限重复提示、复盘时间 |
| 信任 | 来源解释可达、越权事件、删除传播结果、暂停/撤权成功 |
| 搜索 | 搜索按钮可发现、日历定位成功、关键词零结果、范围完整性理解、来源回跳成功 |
| Agent 使用 | ContextPack 有用/不相关/缺失/过时/越权反馈 |
| 留存 | 形成 `今天` 的活跃天数、次周/四周持续使用 |
| 成本 | 每活跃用户存储、同步、OCR、转写、模型、支持和电量成本 |

MVP 不以 Event 数量、采集字节或授权来源数作为北极星。主结果指标为“复盘后一天是否有用”“历史结果是否帮助完成任务”和“低负担获得价值的活跃日”；权限成功率、崩溃率、误事实、越权和删除失败为驱动/护栏，不得通过扩大采集范围改善主指标。

真实阈值必须由 Prototype、封闭测试和单位成本模型确定。

## 10. 产品验收标准

1. 不连接 Agent 的用户能仅靠 Mobile 形成、查看、补充、搜索和删除一天事件。
2. AI 用户能让 Agent 在 exact Grant 内自动写回一个真实任务，并在 Mobile 看到可追溯、可撤销的 Event/Revision。
3. 主动补充离线可保存，处理失败不丢内容，联网后可继续整理。
4. 日历计划、健康无数据和位置缺失都不会被写成错误事实。
5. 搜索页支持向上加载历史日流、日历跳转、日期范围和关键词筛选；所有模式复用同一按日分组布局，并说明参与搜索的空间和设备。
6. 用户能理解事件为何出现，并修改、否认、拆分/合并建议或删除。
7. 删除至少证明单来源、多来源、Summary、索引和离线同步副本的传播结果。
8. iOS/Android 产品语义和数据状态一致，但 UI 不要求像素一致；导航、搜索、列表、日期、弹层、返回、字体和辅助功能使用各自平台原生能力。
9. 所有 P0 能力在产品、交互、架构、隐私和测试中有对应落点。
10. 首次使用可在不授予任何后台权限时进入 `今天`，以后仅在实际触发来源时请求系统权限；拒绝后保持原上下文和替代入口。
11. Agent 的允许、收窄、拒绝、过期、撤销和跨空间失败均有可复跑验收；Mobile 能查看活跃授权和不含内容的访问记录。
12. `今天`、Search、Capture、Event、Settings、Source、Agent 和 Delete 页面覆盖 loading/partial/offline/permission/error/destructive 状态，且符合 `Mobile双端原生页面规格.md`。
13. 埋点不携带事件正文、照片/音频、搜索词、位置、健康值或模型输入；每个核心旅程至少能由事件字典重建开始、结果和失败原因。
14. 结构化导出按空间/日期生成、可校验且不改变源数据；删除任务可查询、可重试并能证明未完成副本。

## 11. Gate 与证据边界

- 当前文档完成只代表产品候选可评审，不代表用户价值、平台能力或技术可行性已验证。
- Gate 1 仍需要正式用户/场景证据和 MVP 定向来源补证。
- Gate 2 需要跑通 `获取 -> Event -> 今天 -> 补充/纠错 -> 历史搜索 -> 删除传播` 的 Prototype。
- Gate 3 所需 PRD、交互、架构/RFC、隐私威胁、指标埋点、成本公式、测试和开发里程碑正本已形成；仍需负责人决策及真实实现/安全/成本证据，不能以正本替代 Gate 通过。

## 12. 三线输入输出契约

### 产品交给交互

- 用户、场景、优先级、自动/询问/条件使用规则、权限与删除后果、验收任务。

### 产品交给研发

- 来源范围、字段权威、空间/保留产品规则、状态语义、MVP 指标和否决条件。

### 交互与研发回写产品

- 平台限制、权限降级、获取/处理延迟、成本、失败恢复和无法满足的体验承诺。
- 产品根据证据收缩、替换或后置能力，不能要求界面或架构掩盖限制。

## 13. 当前待确认与待验证

### 已确认

1. `今天` 为默认首页，右上使用放大镜搜索按钮进入历史；用户界面不使用“找回”作为功能名称。
2. 搜索页使用统一历史日流，上滑负责加载，日历负责跳转，搜索词和日期范围负责筛选。
3. 今日小结在事件流末尾默认显示 2–3 行简版并可展开，数据不足时不生成。
4. 取消“真实一天的最小来源组合”产品前提；工程可为测试选择夹具，但不得将其表达为用户使用门槛。
5. 原始位置、音频、照片缩略图和模型输入缓存采用“本地短期恢复 + 结构化独立保留 + 选定原始才同步 + 删除传播”原则；初始 TTL 由 ADR-005 集中配置，Spike 可收紧，延长 Raw/Restricted 需新安全决策。
6. `今天`、默认搜索页与四类关键状态的语义骨架已确认；通用低保真不是跨平台像素稿。
7. MVP 双端原生 UI 优先：iOS 使用 SwiftUI/系统组件，Android 使用 Jetpack Compose Material 3/系统能力；不建设跨平台自定义 UI 壳。
8. Mobile 页面和状态使用 `Mobile双端原生页面规格.md`；指标、事件和敏感字段禁采使用 `MVP指标与埋点字典.md`。

### 产品负责人最终拍板（D1–D10）

1. D1：同账户设备优先在同一 LAN 内点对点同步；MVP 不建设用户记忆数据云。
2. D2：登录账户对应账户数据归属，不增加用户密钥/助记词门槛；所有已批准设备丢失时旧记忆不可恢复。
3. D3：健康五类能力进入首个公开版本并成为发布门禁。
4. D4：结构化导出为 P1，在 M5 完成。
5. D5：批准 M1–M6 全面研发；Gate 与 release 证据要求不因开工授权而跳过。
6. D6：最低 iOS 18+、Android 14+。
7. D7：Agent 在明确 `autonomous_memory` Grant 内自动读写长期 Event/Revision。
8. D8：Raw 按 A 方案保留并执行 TTL，同时建立 SourceLocator 本地源索引。
9. D9：`今天` 只保留一个悬浮记录按钮，点击后展开文字、语音、照片和导入。
10. D10：先做 5 人 Pilot，再扩展 10–15 人和 iOS/Android 真机矩阵。

正式约束见 `../decisions/`；旧推荐选项不再作为未决项。

### 待验证

1. iOS/Android 照片、位置、健康和后台能力真机差异。
2. 本地优先 + LAN Peer Sync 对搜索完整性和删除传播的影响。
3. 用户是否理解事件状态、检索范围和来源解释。
4. MVP 单位成本、模型升级率和资源影响。
5. 数据稀疏、日中空白、未同步和未授权状态在真机上是否能被用户正确区分。
6. 四类原始/中间数据的恢复窗口、存储成本、后台清理和删除证明，用于回填精确 TTL。

## 14. 研发前产品冻结边界

- **已冻结语义**：首批用户、双主端、六条旅程、P0/P1、`今天`/Search、数据稀疏、原始默认本地、最小 Agent 授权、删除传播和双端原生原则。
- **可由研发细化**：内部类名、模块边界、数据库字段物理布局、队列实现和非用户可见重试参数，但必须遵守正式 Schema/API/状态机。
- **不得静默变化**：任何新增默认采集、记忆数据云、跨空间读取、持续定位/录音、删除例外、用户可见状态合并和 P0 后置。
- **变更流程**：影响上项的变更必须进入正式 PDR/ADR，标出产品、隐私、成本、迁移和测试影响，再由相应负责人批准。
