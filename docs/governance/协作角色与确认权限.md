# Ameme 协作角色与确认权限

## 1. 角色

| 角色 | 责任 | 不能单独决定 |
|---|---|---|
| 产品负责人 | 愿景、优先级、Gate、隐私取舍和发布批准 | 不能用口头结论替代验证证据 |
| 项目协调 | Job、计划、阻塞、状态和跨角色闭环 | 不能自行扩大获批范围 |
| 产品研究 | 用户、市场、来源和商业验证 | 不能把桌面研究当真实用户结论 |
| 产品与设计 | PRD、旅程、规则、错误态和指标 | 不能跳过隐私和技术约束 |
| 架构与工程 | 系统、数据、接口、实现、迁移和可观测性 | 不能未经确认上传真实个人数据或发布生产 |
| 隐私与安全 | 权限、威胁、数据生命周期、合规和事故 | 不能只在发布前补审 |
| 质量与评测 | 测试、模型评测、性能、安全和 Gate 证据 | 不能修改验收标准来制造通过 |
| 发布与运营 | 灰度、监控、回滚、客服和复盘 | 不能未经产品负责人批准发布 |
| Reviewer | 独立检查正确性、证据、规范和风险 | 不替代产品负责人的业务选择 |

## 2. 用户确认点

必须确认：

- 新 Job 的重大范围和计划。
- Gate 选择、用户/场景切换和否决结论。
- 新增高敏数据源、云处理、跨空间使用和第三方 Agent 权限。
- 不可逆迁移、真实用户测试、外部分享和生产发布。

无需重复确认：

- 获批计划内的只读调研、代码实现和本地合成测试。
- 修复测试失败、补索引、补文档和运行健康检查。
- 不改变目标的低风险内部重构。

## 3. 上线 RACI

| 工作 | 产品负责人 | 工程 | 隐私安全 | 质量 | 运营 |
|---|---|---|---|---|---|
| MVP 范围 | A | C | C | C | C |
| 技术方案 | C | A/R | C | C | I |
| 数据权限 | A | R | A/R | C | I |
| 测试 Gate | I | R | C | A/R | I |
| 灰度发布 | A | R | C | C | R |
| 事故响应 | I/A | R | R | C | R |
| 扩量/停止 | A | C | C | C | C |

A：最终负责；R：执行负责；C：参与评审；I：知会。
