# Ameme 产品生命周期与上线门禁

> 文档状态：review_ready  
> 适合读者：产品负责人、产品、研发、设计、安全、测试、运营  
> 人类快速阅读：先看 Gate 总表，再查看当前 Gate 证据  
> AI 阅读提示：执行任务时只读取当前 Gate 和相邻 Gate；不要把后期要求提前包装成当前已完成。

## 1. Gate 决策类型

- `pass`：强制证据齐全，可以进入下一阶段。
- `conditional_pass`：非核心缺口有负责人和截止时间，不影响下一阶段学习目标。
- `hold`：证据不足或风险未解决，保持当前阶段。
- `reject`：关键假设被否决，停止该候选并保留失败记录。

每次 Gate 结论写入 `docs/decisions/`，注明证据、缺口、批准人和生效范围。

## 2. Gate 总表

| Gate | 要回答的问题 | 必须证据 | 用户确认结果 |
|---|---|---|---|
| Gate 0 问题成形 | 这是值得研究的问题吗？ | 愿景、问题、边界、不可妥协原则 | 是否进入正式 Discovery |
| Gate 1 Discovery | 谁在何时需要它，数据从哪里来？ | 用户任务、信任边界、市场、来源可行性、2–3 个候选闭环 | 选择 Prototype 候选 |
| Gate 2 Prototype | 最小闭环技术和体验上可行吗？ | 可复跑样机、真实/合成样本、质量/性能/隐私/成本结果、否决条件 | 是否定义 MVP |
| Gate 3 MVP Ready | 产品和工程可以安全开工吗？ | PRD、体验、架构、数据模型、威胁模型、指标、成本、计划 | 批准 MVP 开发 |
| Gate 4 Feature Complete | 功能是否达到封闭测试门槛？ | 代码、迁移、自动测试、评测、性能、安全、可观测性、删除验证 | 是否开放 Alpha/Beta |
| Gate 5 Beta Ready | 目标用户是否获得价值且系统可信？ | 留存/价值、纠错负担、崩溃/性能、隐私反馈、事故演练 | 是否准备生产发布 |
| Gate 6 Production | 能否安全上线并在出问题时撤回？ | 发布包、合规材料、监控、告警、支持、回滚演练、负责人签字 | 明确版本和发布时间 |
| Gate 7 Post-launch | 应扩量、调整还是停止？ | 生产指标、成本、事故、用户反馈、复盘和下一假设 | 扩量/调整/停止 |

## 3. Gate 0：问题成形

必须完成：

- 产品命题、终局愿景和当前不做什么。
- 隐私、用户控制、可解释和可迁移的基本原则。
- 需要验证的用户、价值、技术和商业假设。

当前状态：已通过，Ameme 已进入 Discovery。

## 4. Gate 1：Discovery

必须完成：

- 至少三类有明显差异的候选用户/场景比较。
- 真实访谈或行为证据，不能只有竞品推演。
- 各候选端的信息源、获取方式、权限、稳定性和成本。
- 通用视图、隔离空间和选择性云共享的信任测试。
- 2–3 个 Prototype 候选：目标用户、闭环、数据最小集、风险、指标和否决条件。

不得以“桌面最容易做”为理由直接通过。

当前状态：进行中。

## 5. Gate 2：Prototype

每个候选必须证明：

- 输入能合法、稳定获取。
- 非结构化内容能进入 SourceObject、Observation、Event/Episode 或 Unknown 状态。
- 结果有来源、置信度和删除传播。
- 用户能看到采集状态、暂停、排除和删除。
- 关键体验价值可测，不只展示漂亮总结。
- 记录 CPU、内存、磁盘、延迟、Token 和云成本。

Prototype 失败也必须产出否决记录和可复现证据。

## 6. Gate 3：MVP Ready

强制正本：

- 产品需求文档和范围外清单。
- 核心用户旅程、权限旅程、错误态和删除旅程。
- 系统架构、数据 Schema、同步模型、模型路由和迁移策略。
- 隐私影响评估、威胁模型和数据保留规则。
- 指标定义、埋点、评测集和单位成本模型。
- 里程碑、负责人、依赖、测试计划和发布策略。

未决定的关键事项必须标为阻塞，不能用“后续优化”掩盖。

## 7. Gate 4：Feature Complete

强制证据：

- 主干构建通过，数据库迁移可前进和回滚。
- 单元、集成、端到端、性能、安全和数据删除测试通过。
- 各端权限说明、暂停、排除、导出和删除可操作。
- 关键路径有日志、指标、trace 和故障降级。
- 模型输出有评测集、失败样本和版本记录。
- 发布候选版本来自固定 commit/tag，可重复构建。

## 8. Gate 5：Beta Ready

至少观察：

- Day Reconstruction / 目标场景还原质量。
- 用户确认时间、纠正率和候选记忆接受率。
- 次周/四周留存或与场景匹配的复用指标。
- 崩溃率、资源消耗、同步失败和数据丢失。
- 用户是否持续开启来源、是否理解权限和删除。
- 单活跃用户的模型、存储和支持成本。

阈值在 Beta 前登记，不能看完结果后再调低。

## 9. Gate 6：Production

发布前必须：

- 隐私政策、服务条款、第三方数据政策和商店要求完成评审。
- 生产环境密钥、备份、恢复、数据迁移、监控和告警就绪。
- 客服 FAQ、数据请求、删除请求和事故响应流程可执行。
- 灰度范围、停止条件、回滚负责人和回滚命令明确。
- 发布说明与已知限制对用户诚实可见。
- 产品负责人明确批准具体版本和环境。

## 10. Gate 7：Post-launch

上线后固定复盘：

- 价值、留存、信任、性能、成本和事故是否满足预登记标准。
- 哪些来源产生价值，哪些只制造噪声或风险。
- 删除、同步和 Agent 调用是否发生越权或用户困惑。
- 决定扩量、修复、缩减范围、重新验证或停止。

复盘写入 `docs/operations/`；影响长期方向的结论写入 `docs/decisions/`。
