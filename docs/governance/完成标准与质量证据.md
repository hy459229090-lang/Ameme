# Ameme 完成标准与质量证据

## 1. 通用完成标准

任何工作标记完成前必须同时满足：

- 目标范围内产物真实存在。
- 验证命令真实运行，结果已记录。
- 已知错误、警告、限制和未覆盖项明确。
- 正本、索引、STATUS 和 Job 状态一致。
- 没有把个人数据、密钥、缓存和生成物提交到仓库。
- 到达 Gate 时已获得对应确认。

## 2. 调研完成

- 问题、范围、方法、样本和日期明确。
- 时效性事实优先使用官方来源并记录链接。
- 推断与事实分开。
- 不仅列能力，还写获取、权限、分类、处理、存储和使用影响。
- 待实测项不得标记为可用。

## 3. Prototype 完成

- 一条端到端闭环可复跑。
- 输入样本、环境和命令明确。
- 输出可回到证据，失败样本被保留。
- 记录性能、资源、成本和隐私边界。
- 有明确继续/否决标准，不因 Demo 好看自动升级为 MVP。

## 4. 功能完成

- 正常、空、错误、权限拒绝、离线和取消路径已处理。
- 单元/集成/端到端测试与风险匹配。
- 指标、日志和 trace 不泄露敏感内容。
- 数据迁移、兼容和回滚可执行。
- 用户可暂停、排除、导出和删除对应数据。
- 文档、接口和测试夹具同步。

## 5. 验证报告完成

- 前五行给出明确 verdict：pass、conditional_pass、hold 或 reject。
- 包含环境、输入、命令、结果、证据路径和已知限制。
- 报告数字可由脚本或原始证据重算。
- 没有用计划结果、手工估计或旧输出冒充本轮实测。

## 6. 发布完成

- 发布候选绑定 commit/tag 和构建产物。
- 自动测试、迁移、安全、性能和删除验证通过。
- 灰度、监控、告警、客服、事故和回滚材料齐全。
- 生产配置与密钥不在仓库。
- 产品负责人批准具体版本和环境。
- 上线后验证和复盘时间已安排。
