# ADR-003：云协调采用模块化单体，不预拆微服务

- 状态：superseded_for_mvp
- 日期：2026-07-13
- 决策人：研发前架构基线
- 影响 Gate：Gate 3–5
- 替代/被替代：被 ADR-006 替代为 MVP 同局域网 Peer Sync；保留为未来云能力候选

## 背景与问题

MVP 需要账户/设备、Grant、同步 envelope、删除 ack、任务和审计，但容量、团队和供应商尚未验证。预拆微服务会放大分布式事务和删除证明难度。

## 约束

- 领域模块和数据所有权必须清楚。
- 同步、撤权、删除有严格优先级和事务要求。
- 语言/云供应商不应在无团队证据时由文档武断选择。

## 候选方案

| 方案 | 价值 | 风险 | 成本 | 证据 |
|---|---|---|---|---|
| 无云 MVP | 最简隐私 | 无跨端、Agent 远程能力 | 低 | 不能完成完整 MVP |
| 模块化单体 + worker | 开发/观测/事务简单 | 需保持模块边界 | 中 | 符合封闭 MVP |
| 微服务 | 独立扩缩容 | 运维、协议、删除复杂 | 高 | 无容量证据 |

## 历史决策

P4 起采用模块化单体 API + durable worker + 事务结构库 + 对象存储适配层。模块至少为 identity/device、policy/grant、sync, job/delete、processing、audit。语言和云产品在团队能力评估后选择；边界由 OpenAPI/Schema 固定。

2026-07-14 产品负责人选择 MVP 不建设用户数据云，本决策不再作为 M1–M6 实现基线。若未来重新引入云 relay/backup，再以新的 SDR/ADR 重新评估，而不是自动恢复本方案。

## 后果与回滚

- 模块禁止跨层直接读写他表，使用内部命令/事务边界。
- 只有观测到独立容量或隔离需求后拆服务。
- P0–P3 可完全本地运行，不等待云栈决定。

## 待验证项

团队语言、托管服务可用性、后台任务/数据库/对象存储成本和地域。
