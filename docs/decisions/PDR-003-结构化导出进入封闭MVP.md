# PDR-003：结构化导出是否进入封闭 MVP

- 状态：accepted（选择 A）
- 日期：2026-07-14
- 决策人：产品负责人授权按专业建议代决
- 影响 Gate：Gate 4–6
- 替代/被替代：无

## 背景与问题

Ameme 保存的是可长期积累的个人事件、修订和来源关系。用户需要能够迁移、检查和带走自己的结构化记录，但导出会增加重新认证、范围快照、Raw 选择、临时文件清理和测试成本。当前 P0 的记录、今天、搜索、Agent 与删除闭环并不依赖导出。

## 约束

- 导出不能包含密钥、未选择空间或未获准 Raw。
- 导出必须在本机生成，任务状态可见、可重试，临时文件有 TTL。
- 删除和导出是两个独立动作；导出失败不得改变原数据。

## 候选方案

| 方案 | 价值 | 风险/成本 | 里程碑影响 |
|---|---|---|---|
| A 结构化导出进入封闭 MVP（推荐） | 建立可迁移和可核查的信任底座 | 增加认证、快照、格式和清理测试 | E7/UX-004，M5 完成；不阻塞 M1–M3 |
| B 推迟到 MVP 后 | 近期范围更小 | 早期用户不能自助带走数据，权利请求需人工处理 | 从 M5 移除，发布前仍需权利响应流程 |
| C 只提供内部调试导出 | 开发排错方便 | 不是用户权利能力，容易误用真实内容 | 不计产品完成，不可替代 A |

## 已接受决议

选择 A，但保持 P1：先冻结结构化格式和范围规则，M5 再实现本机导出；不得阻塞 M1–M3 的本地事件闭环和真机来源验证。首版只导出用户选择空间/日期内的 Event、Revision、Episode、DayLedger、Artifact manifest 与非正文审计摘要；Raw 逐对象另选。

## 后果与回滚

- 若选择 A，发布门需要重新认证、跨空间负测、临时文件清理和版本兼容证据。
- 若选择 B，PRD、页面和 OpenAPI 保留 forward-compatible 契约，但 feature flag 关闭；必须给出人工权利请求路径。
- C 只能作为测试工具，不能在产品文案中称为“导出”。

## 待验证项

格式版本、包大小、移动端分享目标、Raw 逐对象选择体验、离线生成耗时和目标辖区权利要求。
