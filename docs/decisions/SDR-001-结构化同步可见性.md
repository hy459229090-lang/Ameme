# SDR-001：MVP 同步拓扑与数据可见性

- 状态：accepted（产品负责人选择 LAN/P2P 方案）
- 日期：2026-07-14
- 决策人：产品负责人
- 影响 Gate：Gate 3–6
- 替代/被替代：替代原“服务端可读最小 Structured cloud”决议；实现见 ADR-006

## 背景与问题

产品需要多设备同步，但首版不希望建设承载用户记忆的数据云。用户明确选择：同一网络环境下优先同步，让数据在已登录设备之间直接流动。

## 候选方案

| 方案 | 价值 | 风险/限制 | 成本 |
|---|---|---|---|
| A 数据云同步 | 随时跨端、易恢复、远程 Agent 简单 | 需要数据服务器，扩大隐私/运维边界 | 中 |
| B LAN/P2P 同步（已选择） | 无 Ameme 数据云；同网设备可同步 Structured 和获准 Raw | 设备需同时可达；受本地网络权限/后台限制；不能异地恢复 | 中高 |
| C 完全单机 | 隐私/工程最简单 | 没有多设备闭环 | 低 |

## 已接受决议

选择 B：MVP 不建设存放、路由或处理用户记忆内容的 Ameme 云服务器。已登录同一账户的设备在同一局域网中发现彼此，经设备身份校验后点对点交换 append-only envelope、Revision、tombstone、ack/proof；Structured 默认可同步，Raw 仍按对象和空间策略选择。

账户/认证服务只证明账户归属，不存储用户记忆正文、结构化事件、Raw、索引或同步队列。第三方模型调用仍按独立处理授权执行，不等于 Ameme 数据云。

## 产品承诺边界

- “同一网络”不等于可信：发现后仍需同账户、设备身份、会话加密、重放防护和协议版本校验。
- 首次本地网络使用需要系统权限/说明；拒绝后保持单机可用。
- 同步是机会式的：两端都在线且系统允许网络活动时执行，不承诺 iOS/Android 后台实时常驻。
- 远程 Agent 只能访问其同机或当前可达的授权设备；MVP 不承诺设备全离线时远程召回。
- 所有已有设备丢失/离线时，登录账户不能凭空恢复数据；要实现异地恢复必须新增数据云/备份决策。

## 后果与回滚

- ADR-003 云模块化单体对 MVP 标记为 superseded，保留为未来数据云候选。
- P4 从“云协调服务”改为 LAN Peer Sync；不再需要 PostgreSQL/对象存储作为同步前提。
- 协议保持 transport-neutral；未来增加云 relay/backup 时复用 envelope，但必须重新做 PIA/SDR，不能静默上线。
