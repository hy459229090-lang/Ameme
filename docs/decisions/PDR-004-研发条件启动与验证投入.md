# PDR-004：批准完整 M1–M6 研发与验证投入

- 状态：accepted（选择 C）
- 日期：2026-07-14
- 决策人：产品负责人
- 影响 Gate：Gate 1–6
- 替代/被替代：替代原“只条件启动 M1–M2”决议

## 已接受决议

批准 M1–M6 全部研发工作启动并行准备/实现，不再以 Gate 1/2 未完成阻止工程开工。同时批准 D10=A 的验证投入：招募 10–15 名目标用户、先做 5 名 pilot；准备至少 2 台 iPhone、Pixel/AOSP 代表机和 1 台严格后台策略 Android OEM 设备。

## 必须区分的边界

- “批准研发”不等于 Gate 1/2/3 已通过，也不等于公开发布授权。
- M1–M6 可以并行实施，但每个 Release/数据/商店/安全能力仍须满足对应证据门；不允许为了制造进度删除测试或降低隐私门。
- 健康进入公开 MVP，HEALTH-01/商店证据因此成为发布阻断项。
- LAN Sync、自动 Agent 读写、删除和账户设备接入必须先通过负向/攻击测试才能进入真实用户环境。

## 系统与资源基线

- iOS 18.0+；Android minSdk 34（Android 14），初始 targetSdk 36；发布前完成 Android 17/API 37 本地网络权限兼容。
- 估算以 Core 团队为基线：1 iOS、1 Android、2 Core/Agent、1 QA，产品/设计/AI/安全共享；Spike 后重估，不把 14–18 周当承诺。
- 用户研究和真机验证与研发并行，不后置到功能完成后。

## Stop/回滚条件

出现不可接受的健康商店定位、LAN 同步越权/不可用、确认保存丢失、删除假完成、Agent 跨空间自动写入或单位成本不可持续时，暂停相关能力并回到范围/架构决策；不因完整开工授权继续带病放量。
