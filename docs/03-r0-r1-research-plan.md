# Ameme R0/R1 调研计划 v0.1

更新日期：2026-07-13  
状态：执行中

## 1. 本轮目的

本轮不选择 MVP，也不比较页面方案。目标是回答两个基础问题：

1. 哪类用户在什么场景下最需要保存和使用个人记忆？
2. 各端能够以什么成本、权限和可靠性获取支撑这些场景的信息？

## 2. 研究单元

每个研究单元使用同一模板，避免只列信息源：

| 维度 | 要回答的问题 |
|---|---|
| 目标用户 | 谁在这个端和场景里有高频问题？ |
| 用户任务 | 用户想记住、找回、理解或交给 AI 使用什么？ |
| 原始信息 | 文本、图片、音频、视频、元数据、传感器、文件还是页面？ |
| 获取方式 | 后台、系统 API、官方 Connector、导入、一键分享、截图/OCR 或主动表达？ |
| 权限与边界 | 需要什么授权？是否涉及他人？能否暂停、排除和删除？ |
| 分类处理 | 如何识别来源、格式、场景、敏感度和实体？失败时怎么降级？ |
| 存储策略 | 哪些只留本地？哪些可同步？原始内容保留多久？ |
| 使用方式 | 日报、搜索、回顾、提醒、Agent 上下文还是其他任务？ |
| 可行性 | 稳定性、平台限制、开发成本、运行成本和合规风险如何？ |
| 验证方法 | 用什么原型、样本和指标验证？ |

## 3. R0：用户与场景研究

优先研究六类候选用户：

1. AI Native 产品经理、研发和研究者。
2. 会议与沟通密集的管理者、销售和顾问。
3. 学生和长期学习者。
4. 有照片、旅行、家庭记录需求的生活记录者。
5. 关注消费、健康、运动和习惯的自我量化用户。
6. 游戏玩家与数字娱乐用户。

每类用户研究五个任务：

- Capture：什么内容经常想记录但没有记录？
- Recall：什么内容需要时经常找不到？
- Reflect：哪些变化希望跨天、周、月看懂？
- Reuse：哪些历史信息经常需要重新讲给人或 AI？
- Control：哪些内容绝不能被默认采集、混合或共享？

输出：用户-任务-价值矩阵、信任边界、付费触发点和首轮访谈提纲。

## 4. R1：端、场景与信息源研究

### Desktop

研究 Windows 和 macOS 的应用活动、窗口、浏览器、文件系统、Git/终端、日历、通知、会议音频和截图能力。

### Mobile

研究 iOS 和 Android 的照片、位置/活动、健康、日历、通知、文件、截图、分享菜单、语音、账单导入及后台限制。

### Communication

研究邮件、Slack、Teams、飞书、企业微信和微信的官方接口、导出方式、机器人能力、个人数据边界与组织控制。

### Life services

研究支付账单、运动健康、音乐、地图出行、Steam/主机/手游战绩等来源的 API、导出、页面解析和截图识别路径。

### AI/Agent

研究 ChatGPT、Claude、Codex 等会话或产物的官方导出、连接器、MCP/Skill/API 调用和最小权限上下文共享。

输出：多端信息源地图、权限矩阵、结构化程度、获取路径、处理难度、存储建议和风险等级。

## 5. 调研证据等级

从高到低：

1. 操作系统/产品官方文档和 API 文档。
2. 实际设备或本地原型验证。
3. 官方导出样本或真实用户数据样本。
4. 可信第三方技术分析。
5. 用户描述或推测。

任何进入 Prototype 方案的信息源，至少需要达到 1+2 或 1+3；只看到产品宣传不能判定可用。
