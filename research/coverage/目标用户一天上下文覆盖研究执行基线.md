# 目标用户一天上下文覆盖研究执行基线 v0.1

> 状态：`plan_ready`；截至 2026-07-26 尚未招募真实参与者
> 证据等级：研究方案 + 合成工具链，不是市场规模、授权率或真实覆盖结论
> 对应决策：`docs/product/目标用户一天上下文覆盖与来源优先级.md`

## 1. 研究问题

本研究不问“用户愿不愿意用一个日记产品”，而回答四个可执行问题：

1. 每类目标用户一天中，哪些上下文在之后真的需要被找回或复用；
2. Mobile、Agent、Share、日历、照片、Browser、会议、健康、位置等来源各自能证明哪些字段；
3. 每增加一种来源，能减少多少重要遗漏，需要多少操作、权限、修订和社交成本；
4. 哪个最小来源组合足以完成“获得上下文 → 形成事件 → 修订 → 后续使用 → 删除/恢复”闭环。

人工回顾是对照基线，不是绝对真相。参与者可能遗忘，平台日志也可能缺失；两者冲突时保留冲突和不确定性，不强行判定。

## 2. 目标分群与分阶段样本

| 阶段 | 分群 | 建议有效样本 | 目的 |
|---|---|---:|---|
| Pilot | T0 AI 使用者中的知识工作者 | 8 人 × 7 天 | 验证工具、负担、Agent/Mobile/日历最小组合 |
| 扩展 A | T1 管理者/销售/顾问 | 5–8 人 × 7 天 | 验证沟通、会议、承诺与他人数据边界 |
| 扩展 B | T1 学生/创作者/自由职业者 | 5–8 人 × 7 天 | 验证 Browser、文件、素材和项目演变 |
| 扩展 C | T2 生活记录者 | 5–8 人 × 7 天 | 验证照片、日程、地点和主观意义 |
| 扩展 D | T2 自我量化/游戏用户 | 5–8 人 × 7 天 | 验证 Health/Life Service 的垂直增益 |

这些数量用于定性与产品发现，不支持总体比例推断。若要发布用户规模或授权率区间，必须另做有抽样框、地区/平台配额和置信区间设计的量化研究。

## 3. 7 天执行流程

### D−2 至 D0：同意与校准

- 说明每个来源读取范围、原始证据保存位置、研究人员访问范围、退出和删除方式。
- 参与者只开启愿意测试的来源；拒绝权限是有效结果，不要求为完成研究而授权。
- 运行 1 个练习日，确认“事件、计划、感受、重要遗漏、后续复用”的共同含义。
- 记录地区、平台、职业/生活模式和来源可用性；不收集与研究无关的身份信息。

### D1 至 D7：低负担采样

- 白天：只在参与者愿意时使用真实产品主动记录、分享或 Agent 指令；来源状态自动记录为可用、未授权、失败或不可用。
- 每日两次 30 秒以内 Experience Sampling：仅询问此刻是否发生“稍后可能需要记住”的上下文，允许跳过。
- 每晚 10–15 分钟：参与者按时间轴回顾当天，补充系统遗漏的事件、结果、意义和感受，并标注重要度。
- 次日早晨 2–5 分钟：复核前一日编译结果，确认、修订、删除或标记“无法判断”。
- D3/D5/D7：执行固定找回任务，例如恢复项目进度、找一个决定或重建一天；记录是否有帮助及引用来源。

### D8：退出访谈与删除/恢复演练

- 比较最小来源组合，询问哪些权限或提示不可接受。
- 从一个已验证备份恢复到空白测试环境，确认 Today/Search 可读；原始密钥与生产移动恢复仍走独立 Gate。
- 参与者任选一条记录执行“仅删除原始证据”或“删除来源并级联结构化/派生内容”，检查结果是否符合预期。
- 执行研究数据删除或获得明确的限定保留同意。

## 4. 记录单位

每个 `user-day` 只记录研究所需的结构化观测：

| 字段 | 说明 |
|---|---|
| segment / platform / day | 分群、平台和相对研究日 |
| context_type | 10 类上下文之一 |
| source_capability | 来源能力，不使用产品品牌替代能力 |
| source_state | available / not_authorized / failed / unavailable |
| fact_status | observed / user_asserted / planned / inferred |
| observed_fields | 时间、地点、人物、动作、结果、意图、感受、关系、描述 |
| importance | 参与者给出的 low / medium / high |
| compile_outcome | 未形成候选、候选、确认事件、修订、删除 |
| effort | 操作次数、主动输入时长、提示次数 |
| future_use | 找回场景、是否有帮助、是否引用证据 |
| gap_reason | 未确认发生、缺结果、缺意义、身份不明、权限/能力问题 |

未经单独同意，不将正文、联系人、精确位置、健康详情或第三方身份写入研究表。仓库只接受合成夹具、脱敏聚合和复跑脚本。

## 5. 指标与分母

### 5.1 来源漏斗

每种来源分别报告，禁止把不同分母合并：

```text
平台可用率 = 具备该来源能力的人数 / 对应平台目标样本人数
授权意愿率 = 同意开启人数 / 来源可用且看到完整权限说明人数
成功启用率 = 成功产出至少一个有效观测人数 / 同意开启人数
user-day 出现率 = 有该来源有效观测的 user-day / 已启用该来源的有效 user-day
```

### 5.2 覆盖与质量

```text
重要上下文召回 = 来源组合捕获的重要上下文 / 人工回顾确认的重要上下文
独特增量 = 新来源独自补到的重要上下文 / 加入前遗漏的重要上下文
重要遗漏率 = 未被来源组合捕获的重要上下文 / 人工回顾确认的重要上下文
错误候选率 = 被参与者否认的候选 / 展示给参与者的候选
修订率 = 发生事实字段修订的事件 / 已确认事件
单位操作增量 = 独特重要上下文增量 / 用户主动操作数
有效复用率 = 被确认有帮助的找回 / 所有触发的找回任务
```

空白时间不等于遗漏，事件条数、采集字节和在线时长不等于覆盖。样本量不足时只报分子/分母和个案范围，不输出精确百分比。

### 5.3 可服务用户规模

只有在首发地区、平台组合和获客渠道确定后才估算：

```text
可服务用户规模
= 渠道可触达目标用户
× 平台/账户可用率
× 预计授权率
× 来源在目标场景中的使用率
```

每个因子必须注明来源日期、地区、平台、样本与不确定性。宏观智能手机或 AI 用户人数不能直接作为可服务用户规模；当前机器夹具的 `scale_status` 必须保持未验证。

## 6. 来源优先级判定

一个来源进入下一阶段，至少需要同时满足：

- 对目标分群产生可解释的独特重要上下文增量；
- 候选错误、修订和提示负担不抵消增量；
- 权限说明后仍有足够参与者愿意启用；
- 字段证据、lineage、级联删除和恢复路径完整；
- 至少一次后续找回或 Agent 任务证明这些上下文有用。

任一隐私、旁观者、不可删除、不可恢复或平台政策硬门失败，来源保持 `hold`，不得由覆盖分数抵消。持续屏幕/音频采集固定为 P3，除非 P0/P1 的低成本方式被真实证据证明无法满足高价值场景。

## 7. 预注册输出

每个阶段必须产生：

1. 分群 × 上下文 × 来源矩阵，包含分子、分母和缺失数据；
2. 来源漏斗、独特增量、重要遗漏、错误候选、修订、操作和复用结果；
3. 最小充分来源组合及失败个案；
4. 权限拒绝、退出、删除和恢复结果；
5. 对 P0–P3 优先级的继续、缩窄、重跑或拒绝决定；
6. 脱敏方法、原始证据位置、访问人和删除时间。

## 8. 当前 Gate

- `hold`：没有真实参与者与连续 7 天结果，不能声称真实覆盖或授权意愿。
- `hold`：首发地区、平台组合和获客渠道未定，不能声称市场规模。
- `conditional_pass` 候选：合成矩阵、保守编译、删除、恢复和复用规则通过后，只能说明研究与实现工具已准备好。
- `pass` 前置：真实 Pilot 无 P0/P1 隐私或数据完整性问题，至少一个最小来源组合完成有用复用，并可按用户选择删除与恢复。
